# claude 세션 "작업 중 멈춤"·"빈 세션으로 열림" 간헐 이슈 진단법

## 증상

- 스피너가 돌던 claude 세션이 작업이 다 안 끝났는데 멈춰 있음. 간헐적이고 발생 시점 특정 불가.
- **대화가 있던 세션이 앱 재실행 후 빈 세션으로 열림** (진짜 보고된 핵심 증상).

## 빈 세션의 근본 원인 (2026-07-10 확정, 디스크 실측으로 검증)

`claude --resume <X>` 는 **즉시 새 sid Y 로 포크**하고 SessionStart(source=resume) 훅이 Y 를 추적에
기록한다. 그런데 **Y 의 .jsonl 은 첫 활동(프롬프트/응답)이 있어야 생성된다(lazy)**. 따라서:

> 방을 열어두기만 하고(=resume 후 입력 없음) 앱이 재시작되면 → 추적이 transcript 없는 **유령 sid** 를
> 가리킴 → 실행부(`TryBuildDirectLaunch`)가 transcript 못 찾음 → 새 빈 세션으로 시작.
> 이전 대화 X 의 .jsonl 은 디스크에 멀쩡히 있는데 **포인터만 잃는다.**

리빌드 재시작이 잦은 개발 패턴에서 자주 발생("간헐적"의 정체). 실측: 추적 파일 10개 중 3개가 유령 sid.

**수정(2026-07-10):** ① 훅(`Write-Tracked`)이 추적 sid 를 바꿀 때 이전 sid 를 `sessions\<room>.prev.txt`
로 보존 ② 실행 시 추적 sid 의 transcript 가 없으면 `.prev` sid 의 transcript 존재를 확인해 그쪽으로
resume + 추적 파일 치유 ③ 배치 재진입 루프(크래시/수동 /exit)에도 동일 폴백: `--resume %SID%` 실패 시
prev 를 추적 파일에 copy(치유 — 안 하면 SessionStart 가 유령을 .prev 로 덮어 체인 오염)한 뒤
`--resume %PSID%`, 그마저 실패 시 새 세션 ④ **`/clear` 는 .prev 를 삭제** — 안 지우면 "clear 후 입력
없이 재시작" 때 폴백이 지운 대화를 되살린다(의도 위반) ⑤ 방 삭제/영구삭제 시 .prev 파일·prev 세대
transcript 도 정리. diag.log 에 `launch[room]: 추적 sid=… transcript 없음(유령) → prev …` 기록.
검증: 배치 폴백 체인 3케이스(전부실패/prev성공/prev없음) cmd 시뮬레이션 + Write-Tracked 시나리오
실행 테스트 통과. **주의: 앱 재시작 후에야 훅·배치가 재생성돼 적용된다.**
유실된 방 수동 복구: 그 프로젝트의 `~/.claude/projects/<enc>/` 에서 원본 .jsonl 을 찾아
`%APPDATA%\DevezCode\claude\sessions\<room>.txt` 에 그 sid 를 써넣으면 된다.

## 조사 결과 (2026-07-10, 트랜스크립트 4일치 전수 조사)

- **API 에러 / 컨텍스트 초과 / 하드킬(툴 실행 대기 중 뚝 끊김) 흔적: 0건.** 문제 세션들의 턴은 전부 "정상 종료"로 끝나 있었다.
- **사이드바 스피너 표시 파이프라인은 무죄.** `SessionBusyService`의 reconcile 타이머가 main 플래그/서브런 파일 기준으로 4초 주기 재수렴하므로, 턴이 진행 중인데 스피너만 꺼지는 경로는 구조상 막혀 있다. **스피너가 꺼졌다 = Stop 훅이 실제로 발화했다(턴이 정말 끝났다).**
- **앱이 진행 중인 턴을 끊는 유일한 지점** = `TerminalSessionManager.GracefulExitPlan`의 escFirst. 앱 종료·리빌드 재시작·테마 재시작 시 busy인 claude 방에 ESC(턴 취소)→Ctrl+D를 보낸다. **리빌드가 잦은 개발 패턴에서는 이게 "나중에 보니 하다 만 채 멈춰 있음"의 주요 후보.**
- 그 외 원인: 사용자가 직접 누른 ESC, claude가 스스로 턴을 끝냄(질문/중간보고/조기 완료 — 모델 동작), 재시작으로 백그라운드 작업 통지(`<task-notification>`)·입력 큐 유실.

## 다음 발생 시 진단 절차

1. 멈춘 세션의 roomId 특정 — `%APPDATA%\DevezCode\workspace.json`의 `Projects[].Sessions` 또는 `%APPDATA%\DevezCode\claude\lastmsg\<room>.txt` 내용으로 매칭.
2. diag.log에서 그 방의 **마지막 전이** 확인:
   - `GracefulExit … ESC` 줄이 있음 → **앱 종료/재시작이 원인** (작업 취소는 설계 동작)
   - `busy[room]=idle (hook)`만 있음 → **claude가 스스로 턴 종료** → 트랜스크립트(`~/.claude/projects/<enc>/<sid>.jsonl`) 마지막 assistant 메시지에서 왜 끝냈는지 확인
   - `wait[room]=permission/input` 후 조용함 → **입력 대기를 놓친 것** (❗ 표시 누락 여부 확인)
   - `reconcile 정정` 반복 → 상태 파일 오판(표시 버그) 조사
3. 트랜스크립트에서 인터럽트/에러 검색: `Select-String <sid>.jsonl -Pattern 'Request interrupted by user','isApiErrorMessage.:true','Prompt is too long'` — 인터럽트 시각과 diag.log의 Shutdown/GracefulExit 시각을 ±수 초로 대조하면 수동 ESC인지 앱 ESC인지 갈린다.

## 함정

- 종료 로그 `Shutdown: prepare snapshots`는 ESC **전송보다 먼저** 찍힌다(MainWindow.OnWindowClosing 순서). 인터럽트가 Shutdown 로그보다 수십 초 앞서 있으면 앱이 아니라 수동 ESC.
- 트랜스크립트의 usage limit 문구는 사용자가 붙여넣은 타 에이전트(codex) 출력일 수 있음 — `type` 필드로 실제 시스템 메시지인지 확인.
- resume하면 새 session_id의 새 .jsonl로 이어진다 — 하드킬 증거(툴 대기 중 끊긴 꼬리)는 **이전** 파일에 남는다.
