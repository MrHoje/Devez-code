# 세션 추적 이벤트 소유권

## 증상

- 사용자가 입력하지 않은 `Updated Plan` 같은 항목이 완료 기록에 생긴다.
- 실제 루트 턴이 끝나기 전에 스피너가 꺼지거나 완료 카드가 만들어진다.
- resume 대상 세션 ID가 내부 에이전트·자식 CLI 세션 ID로 바뀐다.

## 원인

DevezCode가 최상위 CLI에 주입한 `DEVEZCODE_ROOM_ID`는 그 CLI가 실행한 자식 프로세스에도
상속된다. 자식이 다른 에이전트이거나 같은 CLI의 내부 에이전트여도 훅·플러그인이 방 ID만 보고
상태 파일을 쓰면 부모 방의 `lastmsg`, `busy`, `waiting`, `sessions`를 오염시킨다.

방 ID는 위치만 나타내며 이벤트 생산자의 신원이나 루트 세션 소유권을 증명하지 않는다.

## 필수 방어선

하나만 두지 말고 다음 세 층을 함께 유지한다.

1. **실행 환경 표식**
   - `TerminalSessionManager`가 최상위 실행에 `DEVEZCODE_TRACKING_AGENT=<agentId>`를 주입한다.
   - 생성 배치와 직접 프로세스 환경 모두에 명시한다.
   - 자식은 값을 상속하므로 이 표식만으로 같은 에이전트 중첩은 구분하지 못한다.
2. **생산자 fail-closed**
   - 훅·플러그인·CLI 본체는 표식이 자신의 에이전트 ID와 정확히 일치할 때만 쓴다.
   - 값이 없거나 다른 에이전트면 어떤 상태 파일도 쓰지 않는다.
   - 같은 에이전트의 중첩 세션은 root session 파일 또는 process owner 파일로 추가 차단한다.
3. **앱 소비자 검증**
   - `MainWindow.FindOwnedSession(roomId, sourceAgentId, eventName)`로 방의 실제 `AgentId`와
     이벤트 소스를 비교한 뒤에만 UI 상태, 세션 ID, 완료 기록을 변경한다.
   - `AgentId`가 비어 있으면 저장된 방 설정으로 복원하되, 끝까지 알 수 없으면 거부한다.

## 루트 소유권 방식

| 에이전트 | 방식 |
|---|---|
| Claude | 기존 메인 턴·서브런 추적 |
| Codex, Kimi | `sessions/<room>.root.txt`와 현재 세션 ID가 모두 일치해야 상태 쓰기 |
| Grok, Antigravity | 기존 root/ended 전환 fence |
| OpenCode | `owners/<room>.txt`를 프로세스 PID로 원자적 claim |
| Devez Vibe | CLI 본체가 `owners/<room>.txt`를 `create_new`로 claim하고 정상 종료 때 반납 |
| Gajae | 방마다 별도 `--session-dir`을 사용해 저장소 자체를 격리 |

앱이 새 최상위 OpenCode·Devez Vibe 프로세스를 시작할 때는 비정상 종료가 남긴 owner 파일을 먼저
지운다. 자식 프로세스는 이 런치 경로를 거치지 않으므로 살아 있는 루트의 소유권을 빼앗지 못한다.

## 완료·스피너 정확성 불변식

- 다른 에이전트 이벤트는 방 상태를 절대 변경하지 않는다.
- 같은 에이전트라도 루트가 아닌 세션·프로세스는 `busy`, `waiting`, `lastmsg`, `sessions`를 쓰지 않는다.
- `busy=false`와 완료 기록은 소유권 검증을 통과한 루트 이벤트에서만 발생한다.
- 세션 resume ID는 루트 fence를 통과하고 실제 transcript가 확인된 값만 저장한다.
- 방 삭제와 유령 방 GC는 `.root`, `.prev`, `.good`, `.ended`, `owners` 보조 파일도 함께 정리한다.

## 회귀 검증

```powershell
dotnet run --project Tests\DevezCode.Tracking.Tests\DevezCode.Tracking.Tests.csproj
powershell -NoProfile -ExecutionPolicy Bypass -File Tests\TrackingHooks.Tests.ps1
```

Devez Vibe(dvz) 저장소에서는 다음을 실행한다.

```powershell
cargo test devezcode::tests
```

새 에이전트를 추가할 때는 교차 에이전트 불일치와 같은 에이전트 중첩 루트 두 경우를 모두 테스트한다.
