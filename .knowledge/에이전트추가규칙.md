# 에이전트 추가 규칙 — 신규 AI CLI 통합 체크리스트

> 새 AI CLI 에이전트(Claude Code / Codex / OpenCode / Gajae 외)를 DevezCode에 추가할 때 보는 문서.
> 라인 번호는 참고용(변동됨) — **각 절의 grep 앵커로 실제 위치를 찾는다.**
> 마지막 검증: 2026-07-08 (AgentRegistry에 claude/codex/opencode/gajae 4종 등록 상태 기준)

---

## 0. 먼저 결정: 통합 수준 (Tier)

| Tier | 얻는 것 | 해야 하는 일 |
|------|---------|-------------|
| **1. 최소** | 피커에 표시 + 실행 + ResumeFlag 복원 | §1 코어 등록만 (코드 분기 0개) |
| **2. 세션 영속** | 방별 세션 정확 복원, 앱 재시작·테마 재시작 생존 | §1 + §2 (전용 런치·세션 추적·종료 스냅샷) |
| **3. 풀 통합** | busy 스피너, ❗대기 표시, 헤더 lastmsg, 테마, /exit 자동 재진입 | §1~§4 + 선택 기능(§5~§8) |

기존 4종의 위치: claude=Tier 3, opencode=Tier 3(플러그인 방식), gajae=Tier 3(폴링 방식), codex=Tier 2+훅(UI 숨김).

**세션ID 추적 방식은 3패턴 중 하나를 고른다** (Tier 2 이상 필수):

| 패턴 | 사용 에이전트 | 조건 | 구현 |
|------|--------------|------|------|
| **훅** | claude, codex | CLI가 SessionStart/Stop 훅 지원 | 훅 스크립트가 `%APPDATA%\DevezCode\<agent>\...`에 세션ID 기록 |
| **플러그인** | opencode | CLI가 플러그인 시스템 지원 | `XxxPluginInstaller`가 플러그인 설치, 플러그인이 파일 기록 |
| **파일 폴링** | gajae | CLI가 세션을 로컬 파일(.jsonl 등)로 남김 | 방별 `--session-dir` 지정 후 최신 파일에서 ID 추출 |

## 1. 필수 코어 (모든 Tier)

### 1-1. AgentRegistry — `Services/AgentRegistry.cs`

`AgentRegistry.All` 배열에 `AgentDef` 추가:

```csharp
new()
{
    Id = "<id>",                 // 소문자. 모든 switch/if 분기의 키
    DisplayName = "My Agent",    // UI 표시명
    Provider = "MyProvider",     // 피커 부제목
    ExeNames = new[] { "<id>.exe", "<id>.cmd", "<id>.bat", "<id>.ps1", "<id>" },
    Command = "<id>",            // 기본 실행 명령
    SupportsHooks = false,       // 훅 기반 추적(claude/codex 방식)이면 true
    InlineTui = false,           // alt-screen 안 쓰는 인라인 TUI(gjc)면 true — 로딩 오버레이 해제 기준이 달라짐
    ResumeFlag = null,           // Tier 1 복원용 플래그 (codex "--last", opencode "-c")
}
```

- `HiddenFromUI`에 넣으면 피커·설정에서 숨김(백엔드 동작은 유지 — 현재 codex).
- `InlineTui=true` 안 하면 alt-screen 없는 에이전트는 로딩 스피너가 안 꺼진다.

### 1-2. 아이콘 — `Models/AgentImageConverter.cs` + `Resources/Images/ShellPresets/`

`Convert`의 `switch (id)`에 케이스 추가 + PNG 파일(50×50 권장, 투명 배경) 추가.
다크/라이트별 흑백 변형이 필요하면 opencode 케이스처럼 `isDark` 분기.
미등록 id는 claude 아이콘으로 폴백되므로 **빼먹어도 크래시는 안 나서 눈치 못 챈다** — 반드시 확인.

### 1-3. 여기까지 하면 자동으로 되는 것 (수정 불필요)

- 설정 다이얼로그 에이전트 목록 (`SettingsDialog.BuildAgentList` — `AgentRegistry.All` 순회)
- 세션 생성 피커 (`AgentPickerDialog` — `GetEnabledAndInstalled()`)
- 사이드바/탭 스트립 아이콘 (`AgentImageConverter` 바인딩)
- workspace.json 저장/복원 (`WorkspaceStore.SessionDto.Agent`)
- 방→에이전트 매핑 (`SettingsService.RoomAgents`), 첫 실행 플래그(`IsAgentRoomLaunched`), 활성화 목록(`EnabledAgents`)
- 첫 실행: `cmd /k "<Command>"`, 재실행: `cmd /k "<Command> <ResumeFlag>"` (`TryBuildSimpleLaunch`)

## 2. 세션 영속 (Tier 2) — 런치·추적·종료 스냅샷

### 2-1. LaunchSession 분기 — `Services/Terminal/TerminalSessionManager.cs`

grep 앵커: `agent.Id == "` — 현재 구조(~L115):

```
agent.Id == "codex"     → TryBuildCodexDirectLaunch()    (훅 json + --session-id/resume)
agent.Id == "opencode"  → TryBuildOpenCodeDirectLaunch() (플러그인 설치 + --session <id> + 포크)
agent.Id == "gajae"     → TryBuildGajaeDirectLaunch()    (방별 --session-dir + gjc -r <id>)
agent.SupportsHooks     → TryBuildDirectLaunch()         (claude: 방별 settings + 훅 배치)
그 외                   → TryBuildSimpleLaunch()         (범용 폴백)
```

새 에이전트는 `agent.Id == "<id>"` 분기 + `TryBuildXxxDirectLaunch(roomId, out inject)` 작성.
배치는 `%APPDATA%\DevezCode\<id>\launch\` 아래 `.cmd`로 생성 (기존 `XxxLaunchDir` 패턴 참고, grep: `"DevezCode", "gajae", "launch"`).

**재진입 배치 루프**: claude/gajae는 `goto __reenter` 루프로 실행돼 CLI 내부 `/exit`·Ctrl+C 후 자동으로 같은 세션에 재진입한다(grep: `__reenter`). 새 에이전트도 이 UX가 필요하면 같은 배치 패턴 사용 — 이때 §4 GracefulExitPlan 처리가 반드시 따라온다.

### 2-2. 방별 세션ID 저장 — `Services/SettingsService.cs`

에이전트마다 전용 딕셔너리 + Load/Save 정적 메서드가 관례 (grep: `LoadGajaeRoomSession`):

```csharp
public Dictionary<string, string> XxxRoomSessions { get; set; } = new();  // SettingsData에
public static string? LoadXxxRoomSession(string roomId) ...
public static void SaveXxxRoomSession(string roomId, string sessionId) ...
```

**방 삭제 정리 잊지 말 것** — `RemoveClaudeCodeRoomDir()`에 `Current.XxxRoomSessions.Remove(roomId)` 추가.
안 하면 같은 roomId 재사용 시 예전 세션에 이어붙는다.

### 2-3. 종료 스냅샷 — `TrySnapshotRoomSession` (자주 빠뜨림 ★)

grep 앵커: `TrySnapshotRoomSession`. 앱 종료/테마 재시작 시 방의 최신 세션ID를 settings에 확정 기록하는 `switch (agent.Id)` — **여기에 케이스를 안 넣으면 종료 시점 세션이 유실**되어 "재시작하니 예전 대화가 뜨는" 버그가 된다 (codex에서 실제 발생했던 유형).

### 2-4. DisposeRoom 추적 파일 정리

grep 앵커: `DisposeRoom`. `purgeTracking` 경로에서 새 에이전트의 세션 추적 파일·launch 배치도 삭제 목록에 추가. 앱 종료 정리(grep: `codexDir` ~L1739 부근)에도 에이전트 디렉터리 정리가 있으면 추가.

## 3. 상태 추적 (Tier 3) — busy 스피너 / ❗대기 / lastmsg 헤더

### 3-1. 기존 서비스 지도

`MainWindow.xaml.cs` 상단 필드(grep: `LastMessageService`, ~L63-76)에서 전부 wiring된다:

| 서비스 | 대상 | 방식 | 제공 신호 |
|--------|------|------|----------|
| `SessionBusyService` | claude | 훅이 쓴 `busy/<roomId>.txt` 감시 | busy + waiting(권한/선택지 ❗) |
| `SessionLastMessageService` | claude | 훅이 쓴 `lastmsg/<roomId>.txt` 감시 | lastmsg |
| `CodexHookService` | codex | `hooks.json` 훅 기반 | lastmsg/busy/session_id |
| `OpenCodeBusyService` | opencode | 플러그인 기록 파일 감시 | busy |
| `OpenCodeLastMessageService` | opencode | 플러그인 lastmsg 파일 감시 | lastmsg |
| `GajaeLastMessageService` | gajae | 방 session-dir `.jsonl` 폴링 | lastmsg + busy + ask(❗) 동시 emit |
| `AgentLastMessageService` | 범용 비-claude | (workingDir, agentId) 단위 폴링 | lastmsg |

### 3-2. 새 에이전트 선택지

- 훅 지원 → claude 훅 스크립트 패턴(`busy-hook.ps1`, grep: `busy-hook`) 재사용, `SessionBusyService`류 감시.
- 플러그인 지원 → `XxxPluginInstaller` + opencode 패턴.
- 로컬 세션 파일만 있음 → `GajaeLastMessageService` 패턴(폴링 + 파싱으로 busy/lastmsg/ask 동시 판정).
- 어느 쪽이든 `MainWindow.xaml.cs`에 서비스 필드 + 이벤트 구독 + 방 등록/해제 호출 추가 필요.

busy→idle 전환 토스트는 `MainWindow.NotifyIfSessionFinished()` 공통 경로 — busy 신호만 공급하면 자동.

## 4. 종료 처리 (Tier 3, 재진입 루프 쓰면 필수)

grep 앵커: `GracefulExitPlan`. 에이전트별로 "어떻게 곱게 죽이는가"를 결정:

```csharp
"claude" → (sendShellExit:false, "/exit\r\n", escFirst:busy&&!waiting)  // 텍스트 종료 명령
"gajae"  → (false, "", false)   // 종료 명령 없음 — timeout 후 하드킬
그 외    → (true, null, false)  // 플레인 셸: Ctrl+C×2 + exit
```

- **재진입 배치 루프(`goto __reenter`)를 쓰는 에이전트는 콘솔 Ctrl+C를 보내면 안 된다** — cmd 배치가 "Terminate batch job (Y/N)?"에 걸린다. CLI의 텍스트 종료 명령(claude `/exit` 등)이 있는지 먼저 조사하고 케이스 추가.
- 종료 흐름: GracefulExit → 훅 flush 대기(`WaitForHookFlushAsync`) → `TrySnapshotRoomSession`(§2-3) → Dispose.

## 5. 세션 포크 (선택)

**파일:** `Views/WorkspacePaneView.xaml.cs` (grep: `TryForkGajaeSession`)

포크 가능 에이전트가 **하드코딩 화이트리스트**로 막혀 있다:

```csharp
if (agentId != "claude" && agentId != "opencode" && agentId != "gajae") return;
```

방식 2가지:
- **transcript 복사**: claude/gajae — `TerminalSessionManager.TryForkXxxSession()`이 원본 세션 파일(.jsonl)을 새 ID로 복사. 활성 세션 파일은 `FileShare.ReadWrite`로 읽을 것.
- **CLI 포크 플래그**: opencode — `SettingsService.SaveRoomForkSource()`로 기록해두고 첫 실행에 `--fork` 전달.

새 에이전트 지원 시: 화이트리스트에 추가 + 방식 택1 구현 + 포크 후 세션ID 저장 분기(grep: `SaveRoomForkSource` 주변 if 체인)에 케이스 추가.

## 7. 테마 (선택)

에이전트 TUI에 DevezCode 테마를 입히려면:

- `Services/Terminal/XxxCustomThemes.cs` 생성 (기존: `ClaudeCustomThemes` / `OpenCodeCustomThemes` / `GajaeCustomThemes`)
- `TerminalSessionManager.LaunchSession`의 테마 분기(grep: `isOpenCode = agent.Id`)에 적용 호출 추가
- 테마 변경 라이브 반영: `OnAppThemeChanged` 브로드캐스트 경로에 분기 추가. 테마 변경이 세션 재시작을 요구하면 `GracefulDisposeRoomsAsync` 흐름을 탄다(§4 종료 처리 정상 동작 전제).
- opencode는 재시작 크래시(0xc0000142) 이슈로 앱 레벨 재시작 사용 — 새 에이전트도 프로세스 재시작이 불안정하면 참고.

## 10. 최종 점검 시나리오 (수동 테스트)

Tier에 맞는 항목만 확인:

1. **[T1]** 설정 다이얼로그에 표시되고 설치 감지됨, 피커에 아이콘과 함께 뜸
2. **[T1]** 새 세션 생성 → CLI 정상 기동 (InlineTui 에이전트면 로딩 오버레이가 첫 출력에 해제되는지)
3. **[T2]** 대화 후 앱 재시작 → **같은 대화**로 복원 (다른 방과 안 섞임 — cwd 공유 시 특히)
4. **[T2]** 앱을 강제 재시작 말고 정상 종료 → 재시작: 종료 직전 세션으로 복원 (스냅샷 검증)
5. **[T2]** 방 삭제 후 같은 이름으로 재생성 → 예전 대화가 안 이어짐 (추적 파일 정리 검증)
6. **[T3]** 프롬프트 전송 → 스피너 켜짐 → 응답 완료 → 꺼짐 + 완료 토스트
7. **[T3]** 권한/선택지 질문 → ❗ 표시
8. **[T3]** 헤더에 마지막 프롬프트 표시
9. **[T3]** CLI 내부에서 `/exit`(또는 Ctrl+C) → 자동 재진입으로 같은 세션 복귀
10. **[T3]** 테마 변경 → 세션 재시작 후 TUI 테마 반영 + 대화 유지
11. **[선택]** 세션 우클릭 포크 → 새 세션이 원본 대화 복사본으로 시작, 원본은 무변
12. **[선택]** 텍스트로 내보내기 → .md 생성

## 부록: 기존 4종 요약 비교

| | claude | codex | opencode | gajae |

| 추적 방식 | 훅 | 훅(hooks.json) | 플러그인 | .jsonl 폴링 |

| 포크 | transcript 복사 | ✕ | `--fork` 플래그 | transcript 복사 |
| 내보내기 | O | ✕ | O (CLI export 스폰) | O |
| 테마 | O | ✕ | O (앱 재시작 방식) | O |
| UI 노출 | O | ✕ (HiddenFromUI) | O | O |
