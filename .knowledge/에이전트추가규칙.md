## 1. AgentRegistry — 에이전트 정의 등록

**파일:** `Services/AgentRegistry.cs`

`AgentRegistry.All` 배열에 `AgentDef` 인스턴스를 추가한다.

```csharp
new()
{
    Id = "<id>",                    // 내부 식별자 (소문자, kebab-case)
    DisplayName = "My Agent",       // UI 표시명
    Provider = "MyProvider",        // 제공자명 (피커 부제목)
    ExeNames = new[] {              // PATH 검색용 실행 파일 변형
        "<id>.exe", "<id>.cmd", "<id>.ps1", "<id>",
    },
    Command = "<id>",               // 기본 실행 명령어
    SupportsHooks = false,          // SessionStart/UserPromptSubmit/Stop 훅 지원?
    InlineTui = false,              // alt-screen 안 쓰는 인라인 TUI?
    ResumeFlag = null,              // 재시작 플래그 (codex="--last", opencode="-c")
}
```

| 필드 | 설명 | 필수 |
|------|------|:----:|
| `Id` | 내부 식별자. `AgentImageConverter`의 switch 식과 일치해야 함 | ✓ |
| `DisplayName` | UI 표시명 | ✓ |
| `Provider` | 피커 다이얼로그 부제목 | ✓ |
| `ExeNames` | PATH 검색용 실행 파일 변형 목록 | ✓ |
| `Command` | 기본 실행 명령어 (`TryBuildSimpleLaunch` 경로에서 사용) | ✓ |
| `SupportsHooks` | Claude/Codex처럼 `~/.xxx/hooks.json` 기반 훅 지원 여부 | |
| `InlineTui` | gjc처럼 alt-screen 없이 인라인 렌더링하는지 | |
| `ResumeFlag` | codex의 `--last`, opencode의 `-c` 같은 재시작 플래그 | |

**부수효과:**
- `HiddenFromUI`에 추가하면 설정·피커에서 제외 (codex 용도)
- `DefaultAgentId`는 `"claude"` 고정 — 변경 필요 시 논의

## 2. AgentImageConverter — 에이전트 아이콘

**파일:** `Models/AgentImageConverter.cs`

```csharp
string fileName = id switch
{
    "opencode"  => isDark ? "opencode_icon_white_50.png" : "opencode_icon_black_50.png",
    "claude"    => "claude_code.png",
    "codex"     => "codex.png",
    "gajae"     => "gajae_code.png",
```

- 알 수 없는 id는 Claude 아이콘으로 폴백

## 5. 세션 저장 — SettingsService (방별 데이터)

**파일:** `Services/SettingsService.cs`

방(room) 단위로 저장해야 할 데이터가 여러 종류 있다.

### 5.1 방별 에이전트 ID 매핑 (이미 범용)

```csharp
// RoomAgents: roomId → agentId
Current.RoomAgents[roomId] = agentId;    // SaveAgentForRoom()
```

**수정 불필요** — 이미 roomId 단위로 agentId 저장.

### 5.2 방별 세션 ID 저장 (에이전트마다 별도)

각 에이전트마다 고유한 세션 ID 딕셔너리가 필요하다.
(Claude·Codex·OpenCode·Gajae 모두 별도 딕셔너리 + Load/Save 메서드 보유)

```csharp
// SettingsData 클래스에 딕셔너리 추가
public Dictionary<string, string> NewAgentRoomSessions { get; set; } = new();

// Load/Save 정적 메서드 추가
public static string? LoadNewAgentRoomSession(string roomId)
    => Current.NewAgentRoomSessions.TryGetValue(roomId, out var s) ? s : null;

public static void SaveNewAgentRoomSession(string roomId, string sessionId)
{
    if (string.IsNullOrWhiteSpace(sessionId)) return;
    Current.NewAgentRoomSessions[roomId] = sessionId;
    Save();
}
```

### 5.3 첫 실행 플래그 (범용 — 수정 불필요)

```csharp
// "roomId|agentId" 조합으로 추적 — agentId만 다르면 자동 분리
IsAgentRoomLaunched(roomId, agentId);
MarkAgentRoomLaunched(roomId, agentId);
```

### 5.4 활성화된 에이전트 목록 (범용 — 수정 불필요)

```csharp
LoadEnabledAgents();    // EnabledAgents 리스트
SaveEnabledAgents();
```

### 5.5 방 삭제 시 정리

`RemoveClaudeCodeRoomDir()`에 새 딕셔너리 `Remove`도 추가:

```csharp
public static void RemoveClaudeCodeRoomDir(string roomId)
{
    lock (_lock)
    {
        // 기존 항목들 Remove...
        changed |= Current.NewAgentRoomSessions.Remove(roomId);  // ← 추가
        if (changed) Save();
    }
}
```

## 6. 세션 런치 로직 — TerminalSessionManager

**파일:** `Services/Terminal/TerminalSessionManager.cs`

`LaunchSession` 메서드(~line 99)의 분기문에 새 에이전트 처리를 추가한다.

### 분기 구조 (현재)

```
agent.Id == "codex"     → TryBuildCodexDirectLaunch()    (codex 전용)
agent.Id == "opencode"  → TryBuildOpenCodeDirectLaunch() (opencode 전용)
agent.Id == "gajae"     → TryBuildGajaeDirectLaunch()    (gjc 전용)
agent.SupportsHooks     → TryBuildDirectLaunch()         (Claude)
그 외                   → TryBuildSimpleLaunch()         (범용 fallback)
```

### 새 에이전트 추가 시나리오

**A. 범용 fallback으로 충분한 경우** (가장 간단):
- `TryBuildSimpleLaunch()`가 자동 처리
  - 첫 실행: `cmd /k "<Command>"`
  - 재실행: `cmd /k "<Command> <ResumeFlag>"`
- LaunchSession에 별도 분기 **불필요**

**B. 자체 런치 로직이 필요한 경우:**
1. `agent.Id == "<new-id>"` 분기 추가
2. `TryBuildXxxDirectLaunch(roomId, out inject)` 메서드 작성
3. 필요한 경우 Installer/플러그인 설치 호출

**C. Claude와 동일하게 SupportsHooks=true인 경우:**
- `TryBuildDirectLaunch()`가 자동 처리
- 훅 스크립트가 필요하면 자체 Installer 클래스 필요

### 테마 적용 분기 (~line 138)

```csharp
var isClaude = agent.Id == "claude" && agent.SupportsHooks;
var isOpenCode = agent.Id == "opencode";
// 필요시 추가:
// var isNewAgent = agent.Id == "<new-id>";
```

Claude/opencode처럼 시작 전 테마를 기록해야 하면 분기 추가.

### 방 디렉터리 기억 (~line 166)

```csharp
if (isClaude) _claudeRoomDirs[roomId] = ccDir;
if (isOpenCode) _opencodeRoomDirs[roomId] = ccDir;
// 필요시 추가:
// if (isNewAgent) _newAgentRoomDirs[roomId] = ccDir;
```

## 8. 알림 — 메인 에이전트만, 서브에이전트 제외

**파일:** `MainWindow.xaml.cs`

`NotifyIfSessionFinished()`는 세션의 busy→idle 전환 시 토스트 알림을 표시한다.

```csharp
private void NotifyIfSessionFinished(SessionItem? s, bool wasBusy, bool nowBusy)
{
    if (s == null || !wasBusy || nowBusy) return;
    if (!SettingsService.LoadNotifySessionDoneEnabled()) return;
    // ... 알림 표시 ...
}
```

**⚠️ 현재 문제점:** `NotifyIfSessionFinished`는 **모든 세션**의 busy 변화에 대해 호출된다.
서브에이전트(executor 하위 태스크)가 완료되어도 알림이 뜬다.

### 필요한 확장

**A. `SessionItem`에 메인/서브 구분 플래그 추가:**

```csharp
// Models/WorkspaceModels.cs
public bool IsMainSession { get; set; } = true;  // true=메인(알림 표시), false=서브(알림 없음)
```

**B. `NotifyIfSessionFinished`에서 필터링:**

```csharp
private void NotifyIfSessionFinished(SessionItem? s, bool wasBusy, bool nowBusy)
{
    if (s == null || !wasBusy || nowBusy) return;
    if (!s.IsMainSession) return;  // ← 서브에이전트 알림 제외
    if (!SettingsService.LoadNotifySessionDoneEnabled()) return;
    // ...
}
```

**C. 서브에이전트 세션 생성 시 플래그 설정:**
- 서브에이전트(executor)가 새 세션을 생성할 때 `IsMainSession = false`로 설정
- 서브에이전트 세션도 탭/트리에 표시되지만 알림은 발생하지 않음

## 15. 알림: 메인/서브에이전트 구분 (확장 필요)

**현재 상태:** `NotifyIfSessionFinished`는 모든 세션의 busy→idle 전환에 대해 토스트 알림을 표시한다.
서브에이전트(sub-agent/executor)의 작업 완료 시에도 알림이 뜨는 문제가 있다.

**필요한 확장 작업:**

1. `SessionItem.IsMainSession` (bool) 플래그 추가 (`WorkspaceModels.cs`)
2. `NotifyIfFinished`에서 `s.IsMainSession`이 false면 알림 스킵 (`MainWindow.xaml.cs`)
3. 서브에이전트 생성 시 `IsMainSession = false`로 설정
