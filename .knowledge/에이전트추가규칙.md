# 에이전트 추가 규칙 — 신규 AI CLI 통합 체크리스트

> 새 AI CLI 에이전트(Claude Code / Codex / OpenCode / Gajae 외)를 DevezCode에 추가할 때 보는 문서.
> 라인 번호는 참고용(변동됨) — **각 절의 grep 앵커로 실제 위치를 찾는다.**
> 마지막 검증: 2026-07-14 (AgentRegistry에 claude/codex/grok/antigravity/opencode/gajae 6종 등록.
> antigravity(agy)는 이 문서 전체 절차의 최신 적용 사례 — 훅 + `--conversation` 복원 + cwd 매핑 폴백.
> 런타임 검증 완료(실기, agy 1.1.1):
> · colorScheme enum = **소문자+공백, 대소문자 구분** ("dark" / "solarized dark|light" /
>   "colorblind-friendly dark|light" — "Dark" 는 TUI Settings Error 로 거부).
> · hooks.json 정식 경로 = **~/.gemini/config/hooks.json** (antigravity-cli/ 에 쓰면 agy 가 config/ 로
>   마이그레이션 — 설치기는 처음부터 config 에 쓰고, 새 설치 검증 후에만 구경로의 DevezCode 명령을 정리).
>   최신 schema는 **최상위 named bundle**이며 Pre/PostInvocation·Stop은 flat handler,
>   PostToolUse만 `matcher`+`hooks` wrapper다. 모든 훅은 JSON stdout이 필수(Stop은 `decision` 필수).
> · 훅 command 파싱 제약: **따옴표 보존 + & 해석(cmd 계열)** → 따옴표/특수문자 없는 경로만 안전.
>   stdin JSON 에 **이벤트명 없음**(camelCase 페이로드만) → 이벤트별 등록 시 배치 인자(%1)로 전달.
>   agy 가 훅 프로세스를 조기 취소할 수 있어(--print 의 SessionStart/Stop) **powershell 은 기동 전에
>   죽는다 → ASCII 전용 cmd 배치**(한글 주석은 CP949 파싱 깨짐) + 앱측 stale failsafe(120s)로 idle 보강.
>   PreInvocation/PostInvocation/PostToolUse/Stop + env(DEVEZCODE_ROOM_ID·ANTIGRAVITY_CONVERSATION_ID)
>   발화는 실기 확인 완료. **PreToolUse는 권한 decision 필수라 관찰용 상태 훅을 등록하지 않는다.**
>   **대화형에서도 Stop 훅 프로세스는 조기 취소 확정**(실사용: Stop "executing" 로그는 찍히나 기록 없음,
>   failsafe 120s 로만 idle 됨) → idle 주력은 **transcript 폴링**: agy 가
>   ~/.gemini/antigravity-cli/brain/<conv>/.system_generated/logs/transcript_full.jsonl 에 실시간 기록
>   (type=USER_INPUT|PLANNER_RESPONSE|도구, 내용 있는 마지막 PLANNER_RESPONSE + 정착 10s = idle,
>   도구 직전의 빈 PLANNER_RESPONSE는 완료에서 제외해 장시간 도구 중 오탐 idle 봉인,
>   lastmsg도 USER_REQUEST에서 추출).
> · 키링 블롭 = {token:{access_token…},auth_method} **중첩 구조**, 사용량 API(fetchAvailableModels) 실측 정상.
> · 계정 연결은 grok 패턴 이식: **자체 스토어(antigravity-auth.json) 우선 → agy 키링 폴백** +
>   .disconnected sentinel. 설정창 로그인 창(AntigravityLoginWindow)은 codex/grok 과 동일한
>   WebView2+PKCE, 단 Google 이라 client_secret 도 함께 교환. **OAuth 상수(client_id/secret/scope/
>   redirect)는 바이너리 실측 best-inference — 실제 Google 로그인으로 최종 확정 필요**(Google 의
>   임베디드 WebView 차단 시 시스템 브라우저+loopback 폴백 미구현). 로그인 실패해도 키링 폴백으로 무회귀.
> · 포크 **불가 확정** — db 복사 resume 이 "trajectory not found"(서버측 trajectory 필요, TUI /fork 만 유효).
> 종료는 텍스트 명령 대신 공식 Ctrl+D×2를 사용.)

## 0. 먼저 결정: 통합 수준 (Tier)

| Tier | 얻는 것 | 해야 하는 일 |
|------|---------|-------------|
| **1. 최소** | 피커에 표시 + 실행 + ResumeFlag 복원 | §1 코어 등록만 (코드 분기 0개) |
| **2. 세션 영속** | 방별 세션 정확 복원, 앱 재시작·테마 재시작 생존 | §1 + §2 (전용 런치·세션 추적·종료 스냅샷) |
| **3. 풀 통합** | busy 스피너, ❗대기 표시, 헤더 lastmsg, 테마, 종료 후 자동 재진입 | §1~§4 + 선택 기능(§5~§11) |

기존 4종의 위치: claude=Tier 3, opencode=Tier 3(플러그인 방식), gajae=Tier 3(폴링 방식), codex=Tier 3(훅 방식, xterm6 전용 엔진).

**세션ID 추적 방식은 3패턴 중 하나를 고른다** (Tier 2 이상 필수):

| 패턴 | 사용 에이전트 | 조건 | 구현 |
|------|--------------|------|------|
| **훅** | claude, codex | CLI가 SessionStart/Stop 훅 지원 | 훅 스크립트가 `%APPDATA%\DevezCode\<agent>\...`에 세션ID 기록 |
| **플러그인** | opencode | CLI가 플러그인 시스템 지원 | `XxxPluginInstaller`가 플러그인 설치, 플러그인이 파일 기록 |
| **파일 폴링** | gajae | CLI가 세션을 로컬 파일(.jsonl 등)로 남김 | 방별 `--session-dir` 지정 후 최신 파일에서 ID 추출 |

## 2. 세션 영속 (Tier 2) — 런치·추적·종료 스냅샷

### 2-1. LaunchSession 분기 — `Services/Terminal/TerminalSessionManager.cs`

grep 앵커: `agent.Id == "` — 현재 구조(~L115):

```
agent.Id == "codex"     → TryBuildCodexDirectLaunch()    (훅 json + --session-id/resume)
agent.Id == "opencode"  → TryBuildOpenCodeDirectLaunch() (플러그인 설치 + --session <id> + 포크)
agent.Id == "gajae"     → TryBuildGajaeDirectLaunch()    (방별 --session-dir + gjc -r <id>)
agent.SupportsHooks     → TryBuildDirectLaunch()         (claude: 방별 settings + 훅 배치)
그 외                   → TryBuildSimpleLaunch()         (범용 폴백)
```

새 에이전트는 `agent.Id == "<id>"` 분기 + `TryBuildXxxDirectLaunch(roomId, out inject)` 작성.
배치는 `%APPDATA%\DevezCode\<id>\launch\` 아래 `.cmd`로 생성 (기존 `XxxLaunchDir` 패턴 참고, grep: `"DevezCode", "gajae", "launch"`).

**CLI 종료 후 자동 재진입 — 방식 2가지** (에이전트별 종료 단축키 후 같은 세션 자동 복귀 UX):
- **배치 루프**: claude/gajae — `goto __reenter` 루프 배치로 실행(grep: `__reenter`). 이 방식을 쓰면 §4 GracefulExitPlan 처리가 반드시 따라온다.
- **앱 레벨 재시작**: opencode·codex — 배치 루프 대신 세션 종료 감지 시 앱이 새 ConPTY로 재시작(`TerminalHostView.IsAutoReenterRoom`, grep: `IsAutoReenterRoom`). 10초 창 안 3회 제한으로 무한 크래시 루프 방지(`AllowAutoRestart`). opencode가 배치 재시작 시 0xc0000142 크래시가 나서 택한 방식 — 새 에이전트도 프로세스 재시작이 불안정하면 이쪽.
  **주의**: 앱 종료 중의 Exited 도 이 경로를 타므로 `TerminalSessionManager.IsShuttingDown` 가드가 반드시 필요하다 — 없으면 종료 중에 새 CLI 가 resume 재기동돼 하드킬·세션ID 오염 레이스가 난다(2026-07 codex 에서 수정).

### 2-2. 방별 세션ID 저장 — `Services/SettingsService.cs`

에이전트마다 전용 딕셔너리 + Load/Save 정적 메서드가 관례 (grep: `LoadGajaeRoomSession`):

```csharp
public Dictionary<string, string> XxxRoomSessions { get; set; } = new();  // SettingsData에
public static string? LoadXxxRoomSession(string roomId) ...
public static void SaveXxxRoomSession(string roomId, string sessionId) ...
```

안 하면 같은 roomId 재사용 시 예전 세션에 이어붙는다.

### 2-3. 종료 스냅샷 — `TrySnapshotRoomSession` (자주 빠뜨림 ★)

grep 앵커: `TrySnapshotRoomSession`. 앱 종료/테마 재시작 시 방의 최신 세션ID를 settings에 확정 기록하는 `switch (agent.Id)` — **여기에 케이스를 안 넣으면 종료 시점 세션이 유실**되어 "재시작하니 예전 대화가 뜨는" 버그가 된다 (codex에서 실제 발생했던 유형).

### 2-4. DisposeRoom 추적 파일 정리

grep 앵커: `DisposeRoom`. `purgeTracking` 경로에서 새 에이전트의 세션 추적 파일·launch 배치도 삭제 목록에 추가. 앱 종료 정리(grep: `codexDir` ~L1739 부근)에도 에이전트 디렉터리 정리가 있으면 추가.

## 3. 상태 추적 (Tier 3) — busy 스피너 / ❗대기 / lastmsg 헤더

### 3-1. 기존 서비스 지도

`MainWindow.xaml.cs` 상단 필드(grep: `LastMessageService`, ~L63-76)에서 전부 wiring된다:

| 서비스 | 대상 | 방식 | 제공 신호 |
|--------|------|------|----------|
| `SessionBusyService` | claude | 훅이 쓴 `busy/<roomId>.txt` 감시 | busy + waiting(권한/선택지 ❗) |
| `SessionLastMessageService` | claude | 훅이 쓴 `lastmsg/<roomId>.txt` 감시 | lastmsg |
| `CodexHookService` | codex | `hooks.json` 훅 기반 | lastmsg/busy/session_id |
| `OpenCodeBusyService` | opencode | 플러그인 기록 파일 감시 | busy |
| `OpenCodeLastMessageService` | opencode | 플러그인 lastmsg 파일 감시 | lastmsg |
| `GajaeLastMessageService` | gajae | 방 session-dir `.jsonl` 폴링 | lastmsg + busy + ask(❗) 동시 emit |
| `AgentLastMessageService` | 범용 비-claude | (workingDir, agentId) 단위 폴링 | lastmsg |

### 3-2. 새 에이전트 선택지

- 훅 지원 → claude 훅 스크립트 패턴(`busy-hook.ps1`, grep: `busy-hook`) 재사용, `SessionBusyService`류 감시.
- 플러그인 지원 → `XxxPluginInstaller` + opencode 패턴.
- 로컬 세션 파일만 있음 → `GajaeLastMessageService` 패턴(폴링 + 파싱으로 busy/lastmsg/ask 동시 판정).
- 어느 쪽이든 `MainWindow.xaml.cs`에 서비스 필드 + 이벤트 구독 + 방 등록/해제 호출 추가 필요.
- 범용 `AgentLastMessageService`(비-claude lastmsg)는 세션 활성화 시 `WorkspacePaneView`에서 `AgentLastMsg?.TrackSession(path, agentId)`로 등록된다(grep: `TrackSession`) — 비-claude면 자동 등록되므로 별도 수정 불필요.
- ⚠️ **훅/플러그인이 방별 상태 파일(busy/lastmsg/waiting/session 등)을 쓸 때 직접 `Set-Content` 금지** — truncate 직후 프로세스가 끊기면 0바이트 파일이 남아 idle 전이를 놓치고 스피너가 stuck-ON 된다(codex 2026-07-10 실제 발생). claude `Write-State`(temp+`Move-Item` 원자적 rename) 패턴을 쓴다. 또 앱 측 emit 핸들러는 빈 값을 그냥 무시(return)하지 말고 재확인 후 idle 로 확정할 것. 상세: `.knowledge/훅-상태파일-원자적쓰기.md`.

### 3-3. 완료 알림 (busy→idle 토스트)

`MainWindow.NotifyIfSessionFinished()` (grep: `NotifyIfSessionFinished`) — busy→idle 전환 시 토스트.
현재 4개 busy 소스(claude 훅 / codex 훅 / opencode 플러그인 / gajae 폴링)가 각자 구독 지점에서 호출한다.
새 에이전트도 busy 신호를 이 경로에 연결하면 알림·설정 토글(`LoadNotifySessionDoneEnabled`)이 자동 적용.
claude 경로는 `isStillActive` 콜백(서브에이전트 생존 확인)을 넘긴다 — 훅 방식이면 동일하게.

## 4. 종료 처리 (Tier 3, 재진입 루프 쓰면 필수)

grep 앵커: `GracefulExitPlan`. 에이전트별로 "어떻게 곱게 죽이는가"를 결정:

```csharp
"claude"      → (Ctrl+D, 1회, escFirst:busy&&!waiting)
"codex"       → (Ctrl+C, 2회, escFirst:busy)
"grok"        → (Ctrl+Q, 2회, escFirst:false)
"antigravity" → (Ctrl+D, 2회, escFirst:false)
"opencode"    → (Ctrl+C, 2회, escFirst:false)
"gajae"       → (Ctrl+D, 1회, escFirst:false) + 배치 재진입 종료 플래그
그 외          → (Ctrl+C, 2회, escFirst:false)
```

- 종료 시작 시 `TerminalSession.BeginGracefulExit()`로 일반 입력을 먼저 동결한다. 종료 입력은 **CR/LF·Enter·표시 문자열을 금지**하고 제어키만 허용한다. 정상 종료가 실패하면 timeout 후 Job 하드 정리로 폴백한다. 배치가 Ctrl+C를 받아 `Terminate batch job (Y/N)?`에 걸리더라도 초안을 전송하는 텍스트 종료보다 하드 정리가 안전하다.
- 배치 재진입 루프를 쓰는 에이전트는 종료키로 TUI가 끝난 직후 새 TUI가 뜨지 않도록 방별 종료 플래그를 먼저 남긴다. 배치는 플래그 경로에서만 자체 `exit`로 셸을 닫고, 다음 정상 실행 직전에 플래그를 지운다. 이 `exit`는 TUI 입력에 쓰는 문자열이 아니다.
- 종료 흐름: GracefulExit → 훅 flush 대기(`WaitForHookFlushAsync`) → `TrySnapshotRoomSession`(§2-3) → Dispose.

## 5. 세션 포크 (선택)

**파일:** `Views/WorkspacePaneView.xaml.cs` (grep: `TryForkGajaeSession`)

포크 가능 에이전트가 **하드코딩 화이트리스트**로 막혀 있다:

```csharp
if (agentId != "claude" && agentId != "opencode" && agentId != "gajae") return;
```

방식 2가지:
- **transcript 복사**: claude/gajae — `TerminalSessionManager.TryForkXxxSession()`이 원본 세션 파일(.jsonl)을 새 ID로 복사. 활성 세션 파일은 `FileShare.ReadWrite`로 읽을 것.
- **CLI 포크 플래그**: opencode — `SettingsService.SaveRoomForkSource()`로 기록해두고 첫 실행에 `--fork` 전달.

새 에이전트 지원 시: 화이트리스트에 추가 + 방식 택1 구현 + 포크 후 세션ID 저장 분기(grep: `SaveRoomForkSource` 주변 if 체인)에 케이스 추가.

## 13. 최종 점검 시나리오 (수동 테스트)

Tier에 맞는 항목만 확인:

1. **[T1]** 설정 다이얼로그에 표시되고 설치 감지됨, 피커에 아이콘과 함께 뜸
2. **[T1]** 새 세션 생성 → CLI 정상 기동 (InlineTui 에이전트면 로딩 오버레이가 첫 출력에 해제되는지)
3. **[T2]** 대화 후 앱 재시작 → **같은 대화**로 복원 (다른 방과 안 섞임 — cwd 공유 시 특히)
4. **[T2]** 앱을 강제 재시작 말고 정상 종료 → 재시작: 종료 직전 세션으로 복원 (스냅샷 검증)
5. **[T2]** 방 삭제 후 같은 이름으로 재생성 → 예전 대화가 안 이어짐 (추적 파일 정리 검증)
6. **[T3]** 프롬프트 전송 → 스피너 켜짐 → 응답 완료 → 꺼짐 + 완료 토스트
7. **[T3]** 권한/선택지 질문 → ❗ 표시
8. **[T3]** 헤더에 마지막 프롬프트 표시
9. **[T3]** CLI 내부에서 에이전트별 종료 단축키 → 자동 재진입으로 같은 세션 복귀
10. **[T3]** 테마 변경 → 세션 재시작 후 TUI 테마 반영 + 대화 유지
11. **[선택]** 세션 우클릭 포크 → 새 세션이 원본 대화 복사본으로 시작, 원본은 무변
12. **[선택]** 텍스트로 내보내기 → .md 생성
13. **[선택]** 푸터 사용량 표시 + 설정 토글 동작
14. **[선택]** MCP 매니저에서 백엔드 선택·저장
15. **[선택]** 세션 클리너에 카테고리 표시·정리 동작
16. **[공통]** 한글 IME 매트릭스(§11-2, 상세는 터미널커스텀동작.md §5-3):
    한글 연타 / 응답 중 입력 / Enter 직후 재입력 / 음절+스페이스+재입력 / 조합 중 Ctrl+Enter /
    탭·최소화·팝업 복귀 후 첫 한글 / 좌상단 유령 없음 / 조합 중 커서 안 깜빡+종료 후 복원 / 영문 무영향
