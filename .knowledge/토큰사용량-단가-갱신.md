# 토큰 사용량 비용($) 단가 — 갱신 프로세스

> 세션 헤더의 토큰 사용량 표시(`↓입력 ↑출력 ($비용)`)에서 **비용($) 을 계산하는 모델별 단가**를 바꾸거나
> 새 모델을 추가할 때 보는 문서. "단가 최신화 해줘", "gpt-5.6 단가 넣어줘", "opus 값 바꿔" 등에 이 절차를 따른다.

## 구조 (어디서 뭐가 계산되나)

| 요소 | 위치 | 비고 |
|---|---|---|
| **토큰 집계·비용 계산** | `Services/SessionUsageService.cs` | `ParseClaudeFull`(Claude, message.id 중복 제거)·`ParseCodexUsage`(Codex/Devez Vibe 공통). 요청별 모델·사용량·처리 등급으로 합산하며 파일 크기/수정시각이 바뀔 때 재집계 |
| **내장 기본 단가표** | `SessionUsageService.PriceFor()` | 문자열 `contains` 매칭, **구체적 모델 먼저**. GPT-6(astra·sol·luna), GPT-5.6(sol·terra·luna), 기존 GPT/Claude 모델 지원 |
| **외부 단가(우선)** | `settings.json` 의 `UsagePricing` 배열 | `SettingsService.LoadUsagePricing()`. 있으면 내장값보다 **우선**(덮어쓰기/신규 추가). **재빌드 불필요** |
| **캐시 배수** | 규칙별(`UsagePriceRule.CacheWrite5m/1h/Read`) → 없으면 표준 기본 | 표준 = write 5m ×1.25, 1h ×2, read ×0.1 (입력 단가 대비). 기본 상수 = `SessionUsageService.DefW5m/DefW1h/DefRead`. 공급자/모델별로 다르면 규칙에서 덮어씀 |
| **모델 라벨 축약** | `ShortModel()` | 툴팁/혼합표시용 |

- 단가 단위: **100만 토큰당 달러**(perM).
- **토큰 수는 로그 실측값**(하드코딩 아님). **단가만** 가변.
- 단가는 현재 공시가 환산값이며 과거 청구 시점의 요율을 재현하는 기능은 아니다.
- **Codex/Devez Vibe 캐시 write**: GPT-5.6부터 cache write ×1.25 과금 — `ReadCodexLike` 가 `cache_write_input_tokens` 를
  `CacheWrite5m` 버킷으로 파싱(표준 5m 배수 1.25 와 동일해 공식 재사용). 구 GPT-5 는 이 필드가 0.

## 갱신 방법

### 방법 A — settings.json 만 수정 (권장, 재빌드 불필요)

`%AppData%\DevezCode\settings.json` 의 `UsagePricing` 배열을 편집. 앱 재시작이면 반영(설정 재로드).
위에서부터 먼저 맞는 규칙 사용하므로 **더 구체적인 모델을 위에** 둔다.

```json
"UsagePricing": [
  { "Match": "gpt-6-astra", "InPerM": 10, "OutPerM": 50, "CacheRead": 0.1 },
  { "Match": "opus",    "InPerM": 5,    "OutPerM": 25 },
  { "Match": "sonnet",  "InPerM": 3,    "OutPerM": 15 }
]
```

- `Match`: 모델ID **부분일치**(소문자 비교). 예 `"opus"` 는 `claude-opus-4-8` 매칭, `"gpt-5"` 는 `gpt-5.6-sol` 매칭.
- `CacheWrite5m`/`CacheWrite1h`/`CacheRead`: **생략하면 표준값**(1.25/2/0.1). 음수나 유한하지 않은 단가는 무시한다.
- 배열이 비어 있으면 내장 기본값 사용.
- 설정에 있는 항목은 내장값을 덮어쓴다(신규 모델은 그냥 추가).

### 방법 B — 내장 기본값 수정 (코드)

`SessionUsageService.PriceFor()` 의 내장 `if (m.Contains(...)) return new Price(in, out, DefW5m, DefW1h, DefRead);`
라인 수정/추가. 공시가 변동 반영이나 기본 동봉값 갱신 시. 표준 캐시배수를 통째 바꾸려면 `DefW5m/DefW1h/DefRead`
상수 수정. 수정 후 빌드·커밋.

### ★ 단가 갱신 시 반드시 함께 점검 — 캐시 배수

단가(InPerM/OutPerM)만 보지 말고 **캐시 요율도 확인**한다:
1. **입력·출력 단가** 최신값 (아래 "확인처")
2. **캐시 write 배수** — Anthropic 5m ×1.25 / 1h ×2 유지되는지
3. **캐시 read 배수** — Anthropic ×0.1, OpenAI cached input 비율(현재 ×0.1 가정)이 그대로인지
4. 공급자별로 read 배수가 달라졌으면 해당 규칙에 `CacheRead` 등 명시(방법 A) 또는 상수 조정(방법 B)

캐시 배수가 틀리면 캐시 비중이 큰 세션에서 금액이 크게 어긋난다(캐시 read/write 가 비용의 대부분).

## 최신 단가 확인처

- **Claude**: `claude-api` 스킬의 모델 표(또는 platform.claude.com/docs pricing). Opus $5/$25, Sonnet $3/$15
  (인트로 $2/$10 은 2026-08-31 까지 — 내장표는 정가 기준), Haiku $1/$5, Fable $10/$50.
- **GPT(Codex), 2026-09-23 확인**: [공식 단가표](https://developers.openai.com/api/docs/pricing), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra), [6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol), [6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol).
  - 입력/캐시 읽기/캐시 쓰기/출력 — GPT-6: Astra $10/$1/$12.50/$50, Sol $2/$0.20/$2.50/$10, Luna $0.10/$0.01/$0.125/$0.50.
  - GPT-5.6: Sol $4/$0.40/$5/$20, Terra $2/$0.20/$2.50/$12, Luna $0.20/$0.02/$0.25/$1.20.
  - 5.6 Sol 행사 가격은 공식 자료에서 최소 2026-11-21까지 제공한다고 설명한다. 종료 시 다시 확인한다.
  - GPT-6(`gpt-6-*`) 및 GPT-5.6은 **한 요청 입력이 272000 초과**일 때 입력·캐시 2배, 출력 1.5배. 세션 누적 토큰으로 판단하지 않는다.
  - `gpt-6-sol` 과 `gpt-5.6-sol` 은 부분일치가 겹치지 않는다(`gpt-6` 앞에 `gpt-` 필요).
  - 기록된 `priority`/`fast`는 2배, `flex`/`batch`는 0.5배. 처리 등급이 없으면 표준 요율이며 현재 설정으로 과거 요청 등급을 추측하지 않는다. `auto`나 미지원 등급은 표준 요율의 부분 추정으로 표시한다.

## 요청별 집계와 호환성

- 모델은 `turn_context.model`, 적용 설정은 `event_msg.thread_settings_applied`의 `thread_settings.model/service_tier`에서 읽는다. 대화 본문의 모델 문자열은 사용하지 않는다.
- 첫 `token_usage_record` 전에는 `token_count.total_token_usage`의 차이를 합산한다. 같은 누적은 중복 제외, 감소 시 새 구간으로 처리한다.
- 첫 새 기록부터는 `token_usage_record.usage`를 합산하고 구 `token_count`는 제외한다. `response_id`로 중복 제거하며 `compacted.latest_token_usage_record` 복제도 한 번만 계산한다.
- 신형 요청 합계와 `thread_token_usage`를 대조한다. 누적 불일치, 대응하는 요청 기록 없는 구 누적 증가, 손상된 JSON은 부분 추정으로 표시한다.
- 새 기록에 있는 요약 요청 사용량도 포함한다. 구 기록에 사용량 자체가 없으면 과거 요약 비용은 복구할 수 없다.
- `output_tokens`에 포함된 `reasoning_output_tokens`를 다시 더하지 않는다.
- 요청 경계가 불명확한 구 누적은 장문 할증을 추측하지 않고 부분 추정으로 표시한다.
- 모델/단가 미상 사용량은 토큰만 포함한다. 일부 비용만 계산 가능하거나 처리 등급이 불확실하면 금액 앞 `~`와 툴팁으로 한계를 표시하며, 전부 미상이면 비용을 생략한다.
- 긴 응답 때문에 마지막 128KB에서 모델이나 토큰 기록이 사라져도 파일 전체에서 복원한다. 재시작 후에는 저장된 구 집계값에 의존하지 않고 원본을 재집계한다.
- 회귀 검증: `dotnet run --project Tests/DevezCode.Usage.Tests -c Release`.

## 주의

- 캐시 배수(1.25/2/0.1)는 현행 표준값. 규칙별로 `CacheWrite5m/1h/Read` 로 덮어쓰거나(설정) `DefW5m/DefW1h/DefRead` 상수로 전역 변경(코드).
- 비용은 **API 정가 환산 추정치**. 구독(Max/Pro)으로 쓰면 실제 청구 아님(툴팁 안내 문구 참고).
- 도구 호출료·지역 할증·계약 할인은 포함하지 않는다. 기록이 부족한 과거 세션의 정확한 청구액을 보장하지 않는다.
