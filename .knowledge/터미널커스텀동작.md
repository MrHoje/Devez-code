# 터미널 커스텀 동작 규칙

DevezCode 터미널은 **WebView2 + xterm.js 5.5.0(기본) + 6.0(codex 전용)** 로 렌더한다. 5.5(`xterm.min.js`)와 6.0(`xterm6.min.js`)을 **둘 다 로드**하고(6.0 전역은 `Terminal6`/`FitAddon6`/`WebglAddon6` 으로 스냅샷 후 기본 전역은 5.5 로 복원), `createTerm` 의 `const use6 = (agent === 'codex') && window.Terminal6` 로 **codex 만 6.0 엔진**을 쓴다 — 6.0 은 ?2026 동기화 출력을 렌더러 레벨에서 네이티브 지원해 codex 리페인트 티어링을 근본 차단하고, 다른 에이전트는 6.0 뷰포트/스크롤바 개편의 회귀를 피해 5.5 를 유지한다. 모든 커스텀 입력/마우스/클립보드/IME 동작은 두 파일에 집중돼 있다.

- **프론트엔드**: `Resources/Terminal/web/terminal.html` (xterm, 키/마우스/클립보드/IME/스크롤)
- **호스트(C#)**: `Views/TerminalHostView.cs` (JS↔WPF 브리지, 실제 클립보드 Win32, 폰트/세션 액션)

> **핵심 제약**: WebView2 는 `HwndHost` 라 항상 WPF 위에 그려진다(airspace). WPF 오버레이·`PreviewMouseDown` 이 터미널 표면을 못 덮고/못 본다. → 오버레이(로딩/커튼/토스트)와 클릭 포커스 통지는 **반드시 웹 레이어 안**에서 처리한다.

기준선은 **Windows Terminal(WT) 정합**. 아래 동작은 대부분 "WT 와 똑같이"가 목표다.

## 1. 키보드 단축키

`handleKey()` (terminal.html — `attachCustomKeyEventHandler` 로 grep) 가 모든 키를 가로챈다. **라인 번호는 계속 밀리므로 이 문서는 함수명/문자열 grep 앵커만 쓴다.**
규약: **`false` 반환 = xterm 처리 안 함(PTY 전송 차단)**, **`true` = 셸/에이전트로 그대로 전달**. 우리가 가로채는 키만 `false`.

| 단축키 | 동작 | 비고 |
|---|---|---|

### Ctrl+Enter / Shift+Enter 줄바꿈 시퀀스 (에이전트별)
`ctrlEnterNewlineData()`:
- **gajae(gjc)**: raw LF `\n` — gjc TUI 는 `\x1b\r` 을 Alt+Enter(queue)로 오인
- **claude / opencode / 셸**: `\x1b\r` (WT 정합)

### IME 조합 중 Ctrl+Enter
조합 중 눌리면 줄바꿈을 **먼저 보내지 않고** `compositionend` 로 미룬다(`pendingComposeNewline`). 먼저 보내면 줄바꿈이 확정 글자보다 앞서 PTY 도달 → 마지막 글자가 새 줄로 내려감.
한글 확정 Enter 는 keydown 이 2번(229=조합중 → 13=확정) 오므로, `composeEnterAt` 로 200ms 내 따라오는 비조합 Enter 를 흡수해 줄바꿈 중복 차단.

### 가로채기 가드
- **IME 조합 중**(`isComposing` 또는 `keyCode===229`): Ctrl+Enter 특례만 처리하고 나머지는 전부 통과
- **AltGr**(`getModifierState('AltGraph')`): 문자 입력 → 가로채지 않음
- **죽은 세션**(`entry.dead`): Ctrl+Enter 는 통과. (죽은 세션에서 Enter = 재시작 요청, `onData`)

| 입력 | 동작 | 비고 |
|---|---|---|

| **좌 드래그 후 뗌(mouseup)** | **copy-on-select** — 자동 복사, 선택 하이라이트 유지 | `doCopyKeep`, 다음 프레임에 조회 |
| **우클릭(누르는 즉시, mousedown)** | 선택 있으면 **복사**, 없으면 **붙여넣기** | WT 정합. 누름 1회 처리(뗄 때 추가 없음)  |
| **컨텍스트 메뉴** | 항상 차단(`preventDefault`) |  |
| **Ctrl+휠** | 폰트 확대(위)/축소(아래) | capture + `passive:false` 로 xterm 스크롤보다 먼저 가로챔  |
| **일반 휠** | xterm 스크롤백 스크롤 | 아래로 굴려 바닥 근처면 ybase 스냅(nudge). 단, alt-buffer/마우스 프로토콜 경로는 120단위 누적 정규화(§7 `handleTerminalWheel`)  |
| **아무 곳 mousedown** | `interact` 통지 → 호스트 패널 포커스 승격 | WebView2 HWND 가 WPF 로 클릭 전파 못 함  |
| **Ctrl+클릭(파일 경로)** | 에디터 탭으로 파일 열기(`openFile`) | linkProvider 확장자 정규식 매칭, `ctrlKey`/`metaKey` 필수  |
| **중클릭** | 특별 처리 없음 → xterm/PTY 기본 | button===2 만 처리 |

### 마우스 트래킹 모드 (TUI)
- **claude 등**: DECSET `?1000/1002/1003/1006` 을 **막지 않고 통과**시킨다. → 마우스 클릭/드래그/휠이 앱으로 직접 전달(WT 정합). 드래그 선택은 claude 자체가 하고 OSC 52 로 복사.
- **gjc**: 마우스 모드 DECSET 을 **파서 단계에서 삼킨다**(`swallowMouse`). gjc 는 마우스 트래킹을 무조건 켜지만 자체 선택 렌더가 없어, 삼켜서 항상 **xterm 로컬 선택**을 쓰게 함 → 드래그 하이라이트 + copy-on-select 복원. 삼키는 모드: `1000,1001,1002,1003,1005,1006,1015,1016`. 그 외 DECSET(`?2004/?2026/?25/?1049`)은 통과.

### 우버튼 SGR 리포트 중복 방지
TUI 마우스 모드에선 xterm 이 우버튼 SGR 리포트(`ESC[<2..M/m`)도 PTY 로 보내는데, claude 가 이를 받아 **또** 붙여넣기 → 2회 붙여넣기. `onData` 에서 우버튼 리포트만 걸러 전달 안 함. 판정: `(b&3)===2 && b<64`(우버튼, 휠 제외). 좌/중/휠/모션은 보존.

## 3. 클립보드

### 복사 (JS → C#)
- **경로**: 선택 복사(Ctrl+C / 우클릭 / copy-on-select) → `post({type:'copy'})` → C# `SetClipboardText`
- **C# 구현**(`TerminalHostView.cs` — `SetClipboardText`/`RunClipboardSta` 로 grep): WPF `Clipboard.SetDataObject` 대신 **Win32 직접**(`OpenClipboard`/`EmptyClipboard`/`SetClipboardData(CF_UNICODETEXT)`) 을 **STA 스레드**에서. 이유: WPF 경로는 `OleFlushClipboard` 라 클립보드 뷰어 체인/후킹 앱과 데드락. 점유 시 즉시 반환 + 재시도.

### 붙여넣기 (요청 → C# 읽기 → JS 주입)
- Ctrl+V 등 / 우클릭 → `post({type:'requestPaste'})` → C# `ReadClipboardForPaste`(STA, 8회 재시도, 클립보드는 1회만 열어 스냅샷에서 읽음) → `post({type:'paste'})` → `term.paste()`
- **읽기 우선순위**(`ReadClipboardForPaste`):
  1. **FileDrop** — 탐색기/바탕화면에서 '파일 자체'를 복사한 경우, `FormatFilePathsForInput` 으로 **경로 텍스트**를 붙여넣음. **이미지 파일도 Bitmap 보다 이 형식이 우선**(원본 파일 경로로 붙여넣음).
  2. **Bitmap present 시 `CF_DIB` 직독**(`GetClipboardDibBytes`/`DibToBitmap`) — `%TEMP%\DevezCode\clipboard\clip_<ts>.png` 로 저장 후 **파일 경로**를 붙여넣음(claude 이미지 첨부용). WPF `DataFormats.Bitmap`(CF_BITMAP/HBITMAP)은 캡처 도구의 delayed-rendering 클립보드에서 무효 핸들 → **검은 화면**이 되는 경우가 있어, 실제 픽셀 바이트인 CF_DIB 를 직접 읽어 우회한다(raw OpenClipboard 는 클립보드를 한 번 더 여는 셈이라 **실제 이미지가 있을 때만** 시도).
  3. **UnicodeText** → 4. **Text**

### OSC 52 (TUI 복사 → 실제 클립보드)
- claude/gjc 등이 선택 후 `ESC]52;c;<base64>` 로 복사할 때, 번들 xterm 은 기본 무시(토스트만 뜨고 실제 복사 안 됨). → `registerOscHandler(52)` 로 직접 처리해 Windows 클립보드에 기록.
- **쓰기만** honor. 읽기 질의(payload `?`)는 보안상 무시.

### 복사 토스트
"copied N chars to clipboard" 를 우측 하단에 잠깐 표시(`showCopyToast`). **우리가 직접 복사한 경로에서만**(Ctrl+C/우클릭/copy-on-select/gjc grace). claude 네이티브 복사는 OSC52 라 claude 자체 토스트가 떠서 여기선 안 띄움(중복 방지).

## 4. 에이전트별 특수 처리 요약

| | claude | opencode | gjc(가재코드) |
|---|---|---|---|
| Ctrl+Enter 줄바꿈 | `\x1b\r` | `\x1b\r` | `\n` |
| 마우스 모드 | 통과(앱이 처리) | 통과 | **삼킴**(xterm 로컬 선택) |
| 드래그 선택 | claude 자체 + OSC52 | (셸/앱) | xterm 로컬 + copy-on-select |
| 선택색 | 테마 기본 | 테마 기본 | **gjc 전용 오버라이드** ↓ |
| 스크롤백 클리어(CSI 3J) | 기본 | 기본 | **삼킴**(param==3만) ↓ |

### gjc 선택색 (`gjcSelectionBg`)
gjc 는 xterm 로컬 선택을 쓰므로 `selectionBackground` 만 테마별로 덮음(`selectionForeground` 는 안 건드림 — 색기반 볼드 보존):
- soft(`#f2ede6`) → `#C2D8B0`
- minimal(`#f8fafc`) → `#C5D8F8`
- dark(그 외) → `#264F78`

### gjc Ctrl+C grace
gjc 는 생성 중 고빈도 풀 재페인트(`\x1b[2J`)가 xterm 선택을 지운다 → 드래그 직후 Ctrl+C 가 선택을 못 봐 SIGINT 로 빠져 gjc 중단됨. **최근 선택(800ms grace)** 이 있으면 그걸 복사하고 SIGINT 억제(`onSelectionChange` 로 `lastSelText`/`lastSelAt` 기록). 한 번 더/grace 밖이면 정상 인터럽트.

### gjc 스크롤백 클리어 삼킴
gjc(비멀티플렉서)는 풀 재페인트 때 `\x1b[3J` 로 스크롤백을 비운다 → 첫 휠 시 뷰포트가 맨 위로 튐. `param==3` 만 삼키고 ED 0/1/2(화면 지움)는 통과 → 과거 대화 스크롤 보존.

## 5. IME (한글 조합) — 아키텍처 전체

> 모든 로직은 `setupImeCaretFix()` (terminal.html, grep: `function setupImeCaretFix`) 안에 방(세션)별 클로저로 산다.
> 라인 번호는 변동되므로 **grep 앵커**로 찾을 것.

### 5-0. 문제 모델 (왜 전부 이 모양인가)

- IME 조합 문자열은 **확정 전까지 PTY 로 안 간다** → TUI 는 조합 존재 자체를 모름 → xterm 이 DOM 오버레이 `.composition-view` 로 미리보기를 그리고, 위치를 **논리(하드웨어) 커서**에 붙인다.
- xterm 내부 `updateCompositionElements` 는 커서가 viewport 밖이면 좌표 갱신을 **스킵** → CSS 초기값 `(0,0)` 잔류 = **좌상단 유령 조합**.
- 확정 글자의 **PTY echo 는 왕복 지연**(codex 수십 ms, opencode 는 렌더 배칭으로 수백 ms 가능)이 있다. 한글은 음절마다 `compositionend`→`compositionstart` 가 **같은 keydown 안에서** 연달아 발생 → 새 조합 시작 시점의 커서는 항상 "직전 글자 echo 도착 전" 좌표다.

**에이전트 2부류** — 신규 에이전트 추가 시 첫 판정:

| 부류 | 에이전트 | 특성 |
|---|---|---|
| **A. 자체커서형** | gajae(gjc), grok | DECTCEM 으로 hw 커서 숨기고 자기 캐럿을 셀로 그림. 논리 커서는 아무데나 파킹 → 조합 중 커서 깜빡임 없음(자연스러움) |
| **B. hw커서형** | codex, opencode, devezvibe, **claude** | hw 커서를 입력 캐럿에 둠. 유휴 시 xterm 기본 동기화로도 위치 정확. 단 ①응답 리페인트 중 커서가 출력/statusLine 왕복 ②echo 레이스 ③조합 중에도 블록커서가 계속 깜빡임 |

> **claude 는 2026-08-03 에 A형 → B형으로 재분류됐다.** 과거 claude 전용 반전셀 스캔
> (`scanClaudeBlockCursor`)은 `anchor=claude null cands[0]=` 로 **diag 전량(12,839건) 실패** 중이었고,
> 배경색 셀·블록 글리프도 0건(`alt=`)이었다. 대신 hw 커서가 입력 행에서 음절마다 2칸씩 전진
> (`cur=38,15→17→19`, `type=alternate`) — 지금 claude 는 자체 캐럿을 안 그린다.
> 그래서 앵커가 늘 없어 pin 이 안 걸리고 조합이 파킹된 커서를 따라 엉뚱한 곳에 그려졌다
> (`/permissions` 등으로 파킹 좌표가 입력란에서 멀어질 때 눈에 띔 — 그건 원인이 아니라 계기).
> 수정 = `pinsLogicalCaret` 에 claude 추가 + 하단 예약행 `bottomReserved`(claude 3줄: 구분선 /
> `main | Opus … | ctx` / `⏵⏵ … mode`, 그 외 1줄). **옛 claude 전용 스캔 코드
> (`scanClaudeBlockCursor`/`rememberClaudeCaret`/`anchor=claude*` 진단/`cached` 폴백)는 같은 날 전부
> 삭제**했다 — 영구 0건이라 되살릴 가치가 없다. claude 가 다시 자체 캐럿으로 돌아가면 새로 짜되,
> 반드시 diag 로 `cur=`(hw 커서 파킹 여부)를 먼저 확인할 것.
> `_prepareImeCaret`(숨은 탭 복귀 시 좌표 준비)도 B형 경로(`rememberLogicalCaret`)로 교체됐다.

### 5-1. 증상 ↔ 원인 매트릭스

| 증상 | 원인 | 처방 |
|---|---|---|

### 5-2. 처방 5종 (전부 `setupImeCaretFix` 내부, B형은 `pinsLogicalCaret` 게이트)

**① pin — 조합 중 위치 동결 + 행 고정 추종** (`.ime-fixed` + `--ime-left/top` CSS 변수)
- `compositionstart` 에 앵커 좌표 1회 스냅샷 → `frozenImeCaret` 으로 조합 내내 동결. xterm 이 0ms 루프로 인라인 left/top 을 되돌리므로 `!important` CSS 변수로 무력화(css grep: `.term-container.ime-fixed`).
- 앵커 소스 = **논리 커서**(`buf.cursorY/X` 직독, grep: `rememberLogicalCaret`) — claude 포함 전 B형 공통. 탭 show 직후 `_prepareImeCaret` 가 폴백 좌표(`lastLogicalCaret`)를 선기록해 숨은 탭 복귀 후 첫 음절의 no-pin 을 막는다. (옛 claude 전용 반전셀 스캔·`lastClaudeCaret` 캐시는 2026-08-03 삭제 — §5 부류표 주석 참조.)
- **하단 예약행 앵커 금지**(grep: `bottomReserved`, `lastrow-fallback`): TUI 는 statusLine 재묘화 후 커서를 그 끝에 파킹한다. 그 순간 조합이 시작되면 앵커가 statusLine 우측 끝에 동결 + chain 전파 → "입력 글자가 statusLine 끝에 표시". 입력란은 구조상 하단 예약행 위에 있으므로 — **claude 는 하단 3줄**(구분선 / `main | Opus … | ctx` / `⏵⏵ … mode`), **그 외 B형은 1줄**(statusLine) — 커서가 예약행이면 마지막 유효 입력란 좌표로 폴백하되, 폴백도 같은 기준으로 검증(리사이즈 stale 방지), 없으면 **no-pin**(null) — frozen 이 비므로 compositionupdate/60ms 재적용이 커서 복귀 즉시 자가 치유. chain 소비 클램프 상한도 예약행 바로 위. 앵커 판정은 `imeDiag` 로 `C:\devezLog\diag.log` 에 남는다(`anchor=live/chain/oob/lastrow-fallback`). ⚠ claude 가 하단 UI 줄 수를 바꾸면(3줄 가정 붕괴) 앵커가 전부 거부돼 no-pin 상시화(=수정 전 수준) — 증상 재발 시 `anchor=lastrow-fallback` 연발 여부부터 볼 것.
- **행 고정 추종**(B형, grep: `행 고정 추종`): 완전 동결이 아니라 **같은 행 안의 커서 이동은 앵커 교정으로 수용**한다. 직전 키(영문/스페이스/음절)의 echo 가 늦게 도착하면 조합 시작 앵커가 몇 칸 왼쪽으로 틀리는데, echo 도착 시 커서가 입력란 행에서 우측 이동 → 따라가면 자가 교정. 행이 다른 이동(출력영역/statusLine 왕복 = 원래 '커서 튐' 원인)만 무시. **이거 없으면 chain 이 앵커 오차를 음절마다 전파해 확정 텍스트 좌우 이중상**(실제 겪음).
- **스크롤 재고정**(B형, grep: `스크롤 재고정`): pin/ghost 좌표는 viewport 상대 행이라, 타이핑 중 출력이 스크롤을 밀면 옛 행에 잔류 → "입력란 + 바로 윗줄 두 줄" 유령. `term.onScroll` 에서 고스트 즉시 제거 + 조합 중이면 스크롤 진정 후 80ms 디바운스로 동결 해제·재고정(리페인트 종료 후 커서 = 새 입력란 캐럿. 즉시 재고정하면 바운스 좌표를 잡으므로 디바운스 필수).
- **`apply()` 는 반드시 `isImeComposing` 일 때만 동작**: `compositionstart+60ms` / `compositionupdate+0ms` 지연 타이머가 조합 종료 후 발화하면 `.ime-fixed` 재부착 + chain 오소모(실제 겪은 회귀).

**② chain — 확정 폭 전진 예약** (grep: `chainCaret`)
- `compositionend(e)` 에서 `frozenImeCaret.col + imeCellWidth(e.data)` 를 예약 → **250ms 내** 다음 `compositionstart` 가 1회 소비(소비 시 현재 그리드로 클램프). echo 를 기다리지 않는 결정적 계산이라 연타 덮어씀이 원천 제거된다.
- **무효화 조건(전부 중요)**: ⓐ 비조합 keydown **및 keyup**(keyCode 229 제외 — 스페이스 확정은 keydown 이 `isComposing=true` 라 keyup 에서만 잡힘) ⓑ Ctrl+Enter 조합 중 줄바꿈(`pendingComposeNewline` 전송 시) ⓒ 우측 경계 `cols-4` 이내(입력란 테두리 조기 줄바꿈 — 틀린 행 고정보다 포기가 낫다) ⓓ blur.

**③ ghost — 로컬 echo 선그리기** (grep: `ime-echo-ghost`, `showGhost`, `checkGhostEchoed`)
- chain 이 조합을 예측 위치로 옮기면 확정 글자 자리가 echo 도착까지 빈칸 → 확정 문자열을 그 자리에 **우리가 미리 그린다**(DOM div, `.xterm-screen` 에 append).
- **배경 투명 + 전경 `--term-fg`**: echo 가 같은 글리프를 그리는 순간 이음새 없이 겹침. 연속 확정이 이어지는 위치면 문자열 이어붙임(연타 전체 커버).
- **글자별 셀 경계 고정 렌더 필수**: 통짜 텍스트로 흘리면 DOM 글리프 전진폭이 xterm 셀 경계(한글=정확히 2×cw)와 미세하게 달라 여러 글자에서 어긋남 누적 → 실글자 위에 오프셋 겹침. xterm 처럼 글자마다 절대위치 span 으로 셀 경계에 고정한다.
- **부분 echo 트리밍**: `onRender` 마다 앞에서부터 "실제 버퍼 셀에 나타난" 글자를 고스트에서 잘라내고 앵커 전진 — 이중 묘화 자체를 제거(픽셀 일치해도 안티앨리어싱 겹침 번짐 방지). 전부 도착하면 제거.
- **쓰레기 고스트 즉사**: 고스트 자리 셀에 "다른 실글자"가 그려지면 = 앵커가 틀렸던 확정 증거(실텍스트는 딴 곳) → 600ms 안 기다리고 즉시 폐기. 빈 셀이면 echo 미도착이니 대기.
- **그 외 제거 조건**: ⓐ 600ms 타임아웃(제출로 입력란 비워진 경우 등 안전망) ⓑ Enter/Backspace/Escape/Delete(입력란 내용 자체가 바뀜 — 잔상 방지) ⓒ resize(픽셀 좌표 무효) ⓓ onScroll(행 기준 무효) ⓔ blur. 스페이스/문장부호는 유지(글자는 제자리에 남으므로).

**④ hw 커서 숨김 — 조합/echo 대기 중** (grep: `hideHwCursor`, `maybeRestoreHwCursor`)
- B형은 조합 중에도 블록커서가 깜빡여 부자연 → `compositionstart` 에 숨기고 A형과 동일한 "조합 중 커서 없음" UX 로 맞춘다. **숨김은 2중**(둘 다 `hideHwCursor` 가 걸고 복원이 함께 푼다):
  - **1차 — 정적 CSS 클래스 `.ime-hide-cursor`**(DOM 렌더러 담당): `.xterm-cursor` 의 블록/바/밑줄
    장식과 블링크 애니메이션을 `!important` 로 무력화. 우리 스타일은 재생성이 없어 아래 "스타일시트
    고착"에 면역. 글자(color)는 보존 — 통숨김(opacity:0)은 커서 밑 글자 증발 회귀라 금지.
  - **2차 — 테마 위장** `cursor=배경색, cursorAccent=전경색`(WebGL 렌더러 담당): canvas 는 CSS 가
    안 먹지만 서비스 색을 직독하므로 위장이 통한다. DOM 렌더러에서는 스타일시트 고착 시 무력(아래).
- **복원은 지연(350ms) 복원이다**(`doRestoreHwCursor`/`cursorRestoreTimer`): 조합 종료·`clearGhost()` 때
  즉시 복원하지 않고 350ms 뒤 가드(조합/고스트 재개 시 무산) 통과 시에만 복원. blur 는 강제 즉시 복원.
  - **왜(2026-07-21 diag 로 확정한 간헐 재발 근본 원인)**: 연타 중 음절 사이 틈(compositionend~다음
    compositionstart)에 echo 가 도착하면 clearGhost → "조합 아님+고스트 없음"이 그 틈에 성립 →
    커서가 음절마다 ~100ms 나타남(diag: `cursor-restore clearGhost` ↔ 다음 `cursor-hide` 교차).
    echo 가 다음 조합 시작보다 늦으면 가드에 걸려 증상 없음 → **echo 지연 vs 타자 간격의 레이스**가
    간헐성의 정체(codex 유휴=echo 빠름=깜빡임, 바쁨=정상). "응답 직후에 재발"의 이유.
  - 즉시 복원으로 되돌리지 말 것 — 위 레이스가 그대로 재발한다.
- 라이브 테마 전환(`case 'theme'`)이 theme 을 통째 교체하면 저장분이 낡음 → `el._onThemeSwapped()` 로 저장분 폐기(새 테마가 이미 정상 커서).
- 이 방식(2중)인 이유: xterm 에 커서 숨김 공개 API 없음 / DECTCEM 은 PTY 측 상태라 TUI 소유(우리가
  보내면 어긋남) / CSS 는 WebGL(canvas)에 안 먹고, 테마 위장은 DOM 렌더러 스타일시트 고착에 무력 —
  각자 한쪽 렌더러를 담당해야 전부 커버된다.
- **고착 증상 확진(2026-07-22, state 스냅샷 실측)**: "커서 미숨김"이 한번 발생하면 세션 재실행까지
  지속되던 건 **xterm6 DOM 렌더러의 테마 스타일시트 고착**이었다. 조합 중 실측:
  `svc=#1F1F1E(위장 도달) / cursorEl=rgb(255,255,255)(페인트=원본 커서색 #FFFFFF)` —
  ThemeService 까지는 위장이 가는데 DOM 렌더러의 `_themeStyleElement` 가 화면에 반영 안 됨.
  `_setTheme` 는 매번 `onChangeColors` 를 fire 하고 렌더러 `_injectCss` 구독도 존재하는데도 발생
  (메커니즘 미상 — `state` 로그의 `sheet=` 값으로 계속 관측). 전경색(#E8E8E8)이 아니라 원본
  커서색과 일치하므로 반전 셀 가설은 배제. textarea 네이티브 캐럿도 실측 무죄(op:0, caret 투명).
  - **처방**: 커서 숨김의 1차 수단을 테마 색 교체(스타일시트 경유 = 고착에 취약)에서
    **우리 정적 CSS 클래스**로 교체 — `.ime-hide-cursor` 가 `.xterm-cursor` 의 블록/바/밑줄
    장식과 블링크 애니메이션을 `!important` 로 무력화(css grep: `ime-hide-cursor`). 우리 스타일은
    재생성이 없어 고착 불가능. **글자는 남긴다** — `opacity:0` 통숨김은 커서 밑 글자까지 지워
    중간 편집 시 글자 증발(금지). 테마 위장은 WebGL 렌더러용으로 병행 유지(canvas 는 CSS 무효,
    서비스 색 직독이라 고착 무관).
  - 신호+2s 복원안은 사용자 UX 불호 + 고착 증상과 무관으로 판명되어 revert(96c7654). 350ms 지연 복원 유지.
  - codex 는 렌더 프레임마다 `DECSCUSR 0` 을 연사(~20Hz)한다 — 커서 스타일 리셋일 뿐 색 무관,
    고착과 별개(관측 로그 볼륨 주의).
- **진단 계측**(diag.log, 상시 유지):
  - `cursor-hide r=gl/dom` / `cursor-restore <이유>[-deferred] r=…`: 숨김·복원 발화와 렌더러 종류.
  - `cursor-hide ANOMALY …`: 불변식(`savedCursorColors` ⇔ 테마 위장) 깨짐 — 감지 즉시 재위장(자가치유).
  - `state compose svc=… cursorEl=… ta=[op:… caret:…] view=…`(grep: `dumpImeState`): 조합 중 실제
    페인트 스냅샷(500ms 스로틀) — 고착 층 판별의 핵심. 재발 시 이 라인에서
    ① svc≠배경색 → 테마 서비스까지 위장 미도달 ② cursorEl 배경≠배경색 → 렌더러 페인트 고착
    ③ ta op≠0 또는 caret 불투명 → 네이티브 캐럿 노출 ④ 전부 정상인데 보임 → 다른 깜빡임 주체.
  - `DECSCUSR n` / `DECSET ?12h·DECRST ?12l`: codex 의 커서 스타일/블링크 시퀀스 관측(고착 시점 상관).
  - `update-without-start data=…`: WebView2 가 compositionstart 를 떨어뜨린 증거(blur→focus 직후 기벽)
    — `beginComposition()` 합성으로 커서숨김/pin 자가치유(xterm 내부 `_isComposing` 은 못 고침).
  - `resetImeNow reason=… hadComposition=…`: blur→focus 리셋 원인(`response-timeout`/`initial-focus`/`pointer-stale`)과 발화 시점 추적.
  - `pointer-recover view=x,y composing=… expected=r,c`: 세션 재클릭이 좌상단/화면 밖 고착으로 판정된 근거. 바로 뒤에 `resetImeNow reason=pointer-stale`가 와야 정상 복구 흐름이다.

**⑤ 기존 유지 장치 (건드리지 말 것)**
- 조합뷰 스타일: WT 정합 — 전경색 + 밑줄 + **불투명 배경**(아래 셀 비침 방지).
- **`display:none` 절대 금지**: 조합 textarea 크기 0 → 조합 끊김(한글 입력 불가). 오프스크린 이동도 위험(아래 5-4).
- **포커스 리포팅(DEC 1004) 억제**(C# TerminalHostView): 조합 시 textarea blur 로 `ESC[O` 가 가면 claude 가 커서를 치워 조합 글자 유실 → `ESC[O/I` 미전달.
- 응답 완료 후 stale 조합 리셋(`resetImeNow`/`_resetImeAfterResponse`/`_resetImeOnInitialFocus`) — WebView2 의 compositionend 누락 대비. **정상 idle 에서는 blur→focus 금지**: 다음 입력의 `compositionstart`가 누락되어 B형 커서 숨김/pin이 시작되지 않을 수 있다. 응답 완료 시 실제 `isImeComposing` 상태만 3초 안전망을 걸고, 정상 `compositionend`가 오면 리셋 없이 취소한다.
- **세션 재클릭 복구**(`_recoverStaleImeOnPointerDown`): 보이는 `.composition-view` 가 화면 밖이거나, 입력란이 구조상 좌상단일 수 없는 codex/opencode/claude에서 `(0,0)`이면 고착으로 확정하고 `resetImeNow('pointer-stale', true, true)`로 blur→focus+현재 커서행 동기화한다. 일반 셸/gajae/grok의 정상 첫 셀 입력은 보존한다. 비활성 창의 첫 클릭은 `document.hasFocus()`가 늦을 수 있어 32ms×8회 재시도하며 세대로 이전 클릭을 폐기한다. textarea가 이미 비활성이면 `blur` 이벤트가 재발하지 않으므로 `resetImeNow`가 `clearImeAfterBlur`를 직접 호출해 ghost/pin/커서숨김까지 멱등 정리한다. 모든 클릭에 무조건 blur→focus 하는 방식은 조합 음절 취소 + 다음 `compositionstart` 누락을 만들 수 있으므로 금지.
- 한글 폴백 폰트: `..., 'D2Coding', 'NanumGothicCoding', 'Malgun Gothic', monospace`.

### 5-4. 시행착오 기록 (재시도 금지)

- **오프스크린(-9999px) 폴백**: "좌표 못 찾으면 화면 밖으로" — 지연 apply(조합 종료 후 발화)와 결합해 `.ime-fixed`+오프스크린이 잔류 → **조합이 통째로 안 보이는 회귀**. 폐기. 좌표 없으면 그냥 xterm 기본(잠깐 어긋남)이 낫다.
- **"응답 중 커서 전체 숨김"**: 폐기됨(이전 세션). 커서 숨김은 반드시 조합/고스트 창으로 한정.
- **pin 제거(d89754f)**: "논리 커서를 따라가게" — 응답 리페인트 중 조합뷰가 입력란↔statusLine 왕복. 원상복구됨. pin 은 필수.
- **chain 무효화에 keydown 만 사용**: 스페이스 확정을 못 잡음(keydown 은 `isComposing=true`) → 다음 조합이 1칸 왼쪽에 붙음. keyup 병행 필수.
- 지연 apply 타이머(60ms/0ms)는 조합 종료 후에도 발화한다 — `apply()` 안의 `isImeComposing` 가드 제거 금지.
- **조합 중 완전 동결(모든 커서 이동 무시)**: 직전 키 echo 지연으로 앵커가 틀린 채 시작하면 교정 기회가 없어 chain 이 오차를 전파 → 확정 텍스트 좌우 이중상. "같은 행 이동만 수용" 하는 행 고정 추종으로 대체됨 — 완전 동결로 되돌리지 말 것.
- **고스트 통짜 텍스트 렌더**: DOM 폰트 전진폭 ≠ xterm 셀 경계 → 여러 글자에서 드리프트 누적. 글자별 셀 고정 span 필수.

> 텍스트 렌더링/글자 깨짐 관련은 `.knowledge/텍스트렌더링규칙.md` 도 함께 참조.

## 7. 스크롤 / 렌더링 커스터마이즈 (참고)

- **트랙패드 휠 정규화**(`handleTerminalWheel`): 일반 버퍼의 로컬 스크롤백과 120단위 detent가 확인되는 마우스 휠은 xterm 기존 경로를 그대로 사용한다. 반면 alt-buffer·스크롤백 없는 버퍼·마우스 프로토콜로 전달되는 고해상도 트랙패드 입력은 작은 관성 이벤트가 앱 동작으로 증폭되지 않도록 Windows 휠 델타 120(legacy 값이 없을 때 48px) 누적당 1회만 보낸다. 이벤트 하나당 최대 1회이며 방향 전환·180ms 중단 시 잔여 누적을 초기화한다. 휠 이벤트를 지원하는 마우스 프로토콜은 실제 포인터 셀/픽셀 좌표를 유지하고, 프로토콜이 없거나 휠을 지원하지 않는 X10이면 application cursor mode에 맞는 방향키 시퀀스를 보낸다. Ctrl+휠은 폰트 조절만 수행하고 xterm 스크롤은 차단한다.
  WPF 쪽(터미널 밖 ScrollViewer) 대응은 `Behaviors/PrecisionWheelScroll.cs` — 상세는 `.knowledge/wpf-정밀휠스크롤-전역.md`. **휠 정밀 델타 정책이 WPF/xterm 두 레이어에 나뉘어 있다.**
- **near-bottom sticky follow**(`writeOut`): 일반 터미널은 쓰기 직전 바닥 2줄 이내면 쓴 뒤 맨 아래로 붙임. 인라인 TUI인 codex/gjc는 고빈도 재페인트가 첫 위쪽 휠 반영 전에 바닥 스냅을 예약하지 않도록 `entry.follow`를 사용한다. 위쪽 휠/키 입력에서 즉시 `false`, 다시 논리적 바닥에 닿으면 `true`로 복원한다.
- **휠 다운 nudge 는 반드시 논리 줄 간격(`baseY - viewportY`)으로 판정** (커밋 160c93b): DOM 뷰포트 `scrollTop`(rest)은 codex 의 잦은 재페인트로 논리 ydisp 와 **크게 어긋난다**(위로 200줄 올려도 DOM 은 물리 바닥 `rest==0`. 실측 vpY=460/baseY=672/rest=0). 그래서 rest 로 판정하면 바닥에서 한참 위인데도 발동해 `scrollToBottom` 으로 바닥까지 끌려간다(="아래로는 휠 한 번에 바닥" 회귀. 위로 스크롤은 `deltaY<0` 이라 무영향 → 비대칭 증상). `gap = baseY - viewportY` 가 **1~3줄 이내**(입력창 잘림 보정 구간)일 때만 스냅, `gap<=0`(이미 논리 바닥)이면 skip. gjc 도 동일 경로. (구: `rest>=0 && rest<=cell*6` — 폐기)
- **탭 show 시 뷰포트 scrollTop 재동기**(`resyncViewportScroll`): 숨김(display:none) 중 출력이 쌓이면 DOM scrollTop 이 낡은 값으로 남아, 복귀 후 첫 휠에서 과거로 크게 점프. show 직후(더블 rAF + 220ms) 버퍼 위치(viewportY)에 맞춰 재동기.
- **`_scrollSuppress`**(`suppressScroll`): 슬래시 명령 자동주입(/model·/effort) 후 N회 출력 동안 스크롤 위치 유지. 사용자가 휠 굴리면 즉시 해제. 1.5s 후 강제 0.
- **`_pinBottomUntil`**(`pinBottom`): 인라인 TUI(gjc) resume 재페인트 스크롤 튐 방지 — 지정 시각까지 쓰기 후 항상 맨 아래.
- **동기화 업데이트(?2026) 배칭**(`feedSync`): gjc 멀티플렉서 repaint 를 open~close 한 번의 write 로 모아 입력창 튐 제거. 마커가 chunk 경계에서 잘리면 `syncCarry` 로 보류.
- **WebGL 렌더러**: GPU 렌더. 소수 배율(125/150%)에선 커서 렌더 버그 → DOM 렌더러로 폴백(`disposeWebglIfFractional`). GPU 컨텍스트 로스 시 자동 폴백. 원격/소프트웨어 렌더링에선 비활성. 엔진 자체는 `createTerm` 의 `use6` 로 선택된다(codex=xterm 6.0 + 짝 addon, 그 외=5.5 — 문서 서두 참조).
- **전환 커튼(`xferCover`/`xferReveal`/`fadeNow`/`returnResync`)**: 분할·패널 토글 리플로우 깜빡임을 웹 레이어 단색/이미지 커버로 감춤. `_fitSuppressed` 로 중간 폭 fit 억제 → 최종 폭에서 한 번만 fit. (airspace 관련 상세는 커밋 히스토리·`airspace 깜빡임` 문서 참조)

### 7-1. Claude 응답 중 Backspace 연타 후 화면 조각·우측 밀림 (2026-08-05)

**증상**

- Claude가 응답을 출력하는 중 입력란의 글자를 Backspace로 연속 삭제하면 실제 텍스트보다 왼쪽까지 지워진 것처럼 보이고, 이후 글자·diff 행 조각이 우측으로 밀린다.
- 긴 색상 diff처럼 일부 내용에서만 두드러지며, 위로 스크롤하면 우측 조각이 늘고 아래로 내리면 다시 줄어든다. 스크롤이 Claude 전체 프레임 재묘화를 유발해 이미 어긋난 셀의 노출 범위가 바뀌는 것이다.
- 2026-08-05 실측 세션은 Claude Code `2.1.222`, `xterm 5.5.0 + WebGL`, `dpr=1`, `127x42` 고정이었다. 발생 시 실제 cols/rows 변화가 없어 WPF 줄높이·resize가 직접 원인은 아니었다.

**원인**

- Claude는 시작할 때 `XTVERSION`(`CSI > 0 q`)으로 터미널 식별 응답을 기다린다. xterm 7 이전 버전은 이 질의에 응답하지 않는다.
- 미응답 경로의 Claude 입력 증분 렌더는 커서가 캐럿 다음 셀에 있다고 가정해 선행 `BS`(`0x08`)를 출력하지만, 실제 전체 프레임은 커서를 캐럿 셀에 둔다. 따라서 Backspace/첫 키가 한 칸 왼쪽 셀을 건드리고, 우측만 지우는 `CSI K`로는 왼쪽에 남은 셀을 제거하지 못한다.
- 응답 출력과 연속 Backspace가 겹치면 이 한 칸 오차와 부분 재묘화가 반복되어 화면 버퍼만 틀어진다. Claude의 논리 입력값은 정상일 수 있어 제출 내용과 화면이 달라질 수 있다.
- 근거: `anthropics/claude-code#81175`의 Claude `2.1.219` + xterm.js 6 재현과 바이트 추적, `xtermjs/xterm.js#5502`의 xterm 7 `XTVERSION` 구현.

**처리** (`Resources/Terminal/web/terminal.html`, grep: `CLAUDE_XTVERSION_BACKPORT`)

- `createTerm`에서 **Claude 방에만** `{ prefix: '>', final: 'q' }` CSI handler를 등록한다.
- 파라미터가 없거나 `0`이면 xterm 7과 같은 `DCS >|xterm.js(5.5.0) ST`(`ESC P>|xterm.js(5.5.0) ESC \\`)를 ConPTY에 돌려준다. `Ps > 0`은 처리만 하고 응답하지 않는다.
- 이 응답으로 Claude가 지원 터미널 경로와 동기화 출력(`?2026`)을 선택하면, 기존 `feedSync`가 프레임을 한 번의 `term.write()`로 모아 중간 재묘화 노출도 함께 줄인다.
- ANSI 출력 스트림·Backspace 키·xterm BufferLine을 변조하지 않는다. 다른 에이전트와 일반 셸에는 handler 자체가 없다.

**회귀 경계·롤백**

- `CLAUDE_XTVERSION_BACKPORT=false` 한 줄로 xterm 5 기본 미응답 상태로 즉시 되돌린다.
- 모든 `BS`를 제거하거나 입력을 디바운스하지 말 것. `BS`는 정상 커서 이동에도 사용되므로 전역 필터는 입력 편집을 깨뜨린다.
- 우측 잔상 셀을 추측해 지우거나 전체 화면 clear를 주입하지 말 것. 정상 diff 배경·현재 입력·스크롤 위치를 손상시킬 수 있다.
- 버전 질의는 Claude 프로세스 시작 때 끝난다. 앱 업데이트 뒤에도 **이미 실행 중이던 Claude 세션은 그대로**이므로 새 세션으로 검증한다.

**검증**

- 번들 xterm 5를 headless Edge에서 열고 `CSI > 0 q`를 주입해 응답 hex가 `1b503e7c787465726d2e6a7328352e352e30291b5c`인지 확인했다.
- `terminal.html` 인라인 JavaScript 3개 구문 파싱, Claude-only 게이트·롤백 상수 정적 검사, `git diff --check`를 통과했다.

## 8. 주의사항 (수정 시)

1. **`handleKey` 반환값 규약 절대 혼동 금지**: `false`=차단, `true`=통과. 새 단축키 추가 시 IME/AltGr 가드 **뒤**에 두되, Ctrl+Enter 특례는 그 **앞**에 유지.
2. **마우스 모드 통과 정책**: claude 등의 DECSET 을 함부로 삼키지 말 것(휠/클릭 전달 깨짐). gjc 만 예외.
3. **클립보드는 반드시 STA + Win32 경로**: WPF `Clipboard.*` 직접 호출 금지(후킹 앱 데드락).
4. **오버레이·포커스는 웹 레이어 안에서만**: WebView2 airspace 때문에 WPF 오버레이로 터미널 못 덮음.
5. **조합뷰 `display:none` 금지**, 포커스 리포팅 억제 유지 — 안 그러면 한글 입력 깨짐.
6. **`Resources/Terminal/web/terminal.html` 이 원본**. `bin/` 은 빌드 복사본이니 편집 금지.
