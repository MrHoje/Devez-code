# 터미널 커스텀 동작 규칙

DevezCode 터미널은 **WebView2 + xterm.js 5.5.0** 로 렌더한다. 모든 커스텀 입력/마우스/클립보드/IME 동작은 두 파일에 집중돼 있다.

- **프론트엔드**: `Resources/Terminal/web/terminal.html` (xterm, 키/마우스/클립보드/IME/스크롤)
- **호스트(C#)**: `Views/TerminalHostView.cs` (JS↔WPF 브리지, 실제 클립보드 Win32, 폰트/세션 액션)

> **핵심 제약**: WebView2 는 `HwndHost` 라 항상 WPF 위에 그려진다(airspace). WPF 오버레이·`PreviewMouseDown` 이 터미널 표면을 못 덮고/못 본다. → 오버레이(로딩/커튼/토스트)와 클릭 포커스 통지는 **반드시 웹 레이어 안**에서 처리한다.

기준선은 **Windows Terminal(WT) 정합**. 아래 동작은 대부분 "WT 와 똑같이"가 목표다.

## 1. 키보드 단축키

`handleKey()` (terminal.html:385) 이 `attachCustomKeyEventHandler` 로 가로챈다.
규약: **`false` 반환 = xterm 처리 안 함(PTY 전송 차단)**, **`true` = 셸/에이전트로 그대로 전달**. 우리가 가로채는 키만 `false`.

### Ctrl+Enter / Shift+Enter 줄바꿈 시퀀스 (에이전트별)
`ctrlEnterNewlineData()` (`:379`):
- **gajae(gjc)**: raw LF `\n` — gjc TUI 는 `\x1b\r` 을 Alt+Enter(queue)로 오인
- **claude / opencode / 셸**: `\x1b\r` (WT 정합)

### IME 조합 중 Ctrl+Enter
조합 중 눌리면 줄바꿈을 **먼저 보내지 않고** `compositionend` 로 미룬다(`pendingComposeNewline`, `:362`/`:394`). 먼저 보내면 줄바꿈이 확정 글자보다 앞서 PTY 도달 → 마지막 글자가 새 줄로 내려감.
한글 확정 Enter 는 keydown 이 2번(229=조합중 → 13=확정) 오므로, `composeEnterAt` 로 200ms 내 따라오는 비조합 Enter 를 흡수해 줄바꿈 중복 차단(`:401`).

### 가로채기 가드
- **IME 조합 중**(`isComposing` 또는 `keyCode===229`): Ctrl+Enter 특례만 처리하고 나머지는 전부 통과(`:405`)
- **AltGr**(`getModifierState('AltGraph')`): 문자 입력 → 가로채지 않음(`:406`)
- **죽은 세션**(`entry.dead`): Ctrl+Enter 는 통과. (죽은 세션에서 Enter = 재시작 요청, `onData` `:773`)

### 마우스 트래킹 모드 (TUI)
- **claude 등**: DECSET `?1000/1002/1003/1006` 을 **막지 않고 통과**시킨다(`:280`). → 마우스 클릭/드래그/휠이 앱으로 직접 전달(WT 정합). 드래그 선택은 claude 자체가 하고 OSC 52 로 복사.
- **gjc**: 마우스 모드 DECSET 을 **파서 단계에서 삼킨다**(`swallowMouse`, `:701`). gjc 는 마우스 트래킹을 무조건 켜지만 자체 선택 렌더가 없어, 삼켜서 항상 **xterm 로컬 선택**을 쓰게 함 → 드래그 하이라이트 + copy-on-select 복원. 삼키는 모드: `1000,1001,1002,1003,1005,1006,1015,1016`. 그 외 DECSET(`?2004/?2026/?25/?1049`)은 통과.

### 우버튼 SGR 리포트 중복 방지
TUI 마우스 모드에선 xterm 이 우버튼 SGR 리포트(`ESC[<2..M/m`)도 PTY 로 보내는데, claude 가 이를 받아 **또** 붙여넣기 → 2회 붙여넣기. `onData` 에서 우버튼 리포트만 걸러 전달 안 함(`:780`). 판정: `(b&3)===2 && b<64`(우버튼, 휠 제외). 좌/중/휠/모션은 보존.

## 3. 클립보드

### 복사 (JS → C#)
- **경로**: 선택 복사(Ctrl+C / 우클릭 / copy-on-select) → `post({type:'copy'})` → C# `SetClipboardText`
- **C# 구현**(`TerminalHostView.cs:728`): WPF `Clipboard.SetDataObject` 대신 **Win32 직접**(`OpenClipboard`/`EmptyClipboard`/`SetClipboardData(CF_UNICODETEXT)`) 을 **STA 스레드**에서. 이유: WPF 경로는 `OleFlushClipboard` 라 클립보드 뷰어 체인/후킹 앱과 데드락. 점유 시 즉시 반환 + 재시도.

### 붙여넣기 (요청 → C# 읽기 → JS 주입)
- Ctrl+V 등 / 우클릭 → `post({type:'requestPaste'})` → C# `ReadClipboardForPaste`(STA, 8회 재시도, `:853`) → `post({type:'paste'})` → `term.paste()`
- **이미지 우선**: 클립보드에 Bitmap 있으면 `%TEMP%\DevezCode\clipboard\clip_<ts>.png` 로 저장 후 **파일 경로**를 붙여넣음(claude 이미지 첨부용, `:862`). 없으면 UnicodeText → Text.

### OSC 52 (TUI 복사 → 실제 클립보드)
- claude/gjc 등이 선택 후 `ESC]52;c;<base64>` 로 복사할 때, 번들 xterm 은 기본 무시(토스트만 뜨고 실제 복사 안 됨). → `registerOscHandler(52)` 로 직접 처리해 Windows 클립보드에 기록(`:681`).
- **쓰기만** honor. 읽기 질의(payload `?`)는 보안상 무시.

### 복사 토스트
"copied N chars to clipboard" 를 우측 하단에 잠깐 표시(`showCopyToast`, `:491`). **우리가 직접 복사한 경로에서만**(Ctrl+C/우클릭/copy-on-select/gjc grace). claude 네이티브 복사는 OSC52 라 claude 자체 토스트가 떠서 여기선 안 띄움(중복 방지).

## 4. 에이전트별 특수 처리 요약

| | claude | opencode | gjc(가재코드) |
|---|---|---|---|
| Ctrl+Enter 줄바꿈 | `\x1b\r` | `\x1b\r` | `\n` |
| 마우스 모드 | 통과(앱이 처리) | 통과 | **삼킴**(xterm 로컬 선택) |
| 드래그 선택 | claude 자체 + OSC52 | (셸/앱) | xterm 로컬 + copy-on-select |
| 선택색 | 테마 기본 | 테마 기본 | **gjc 전용 오버라이드** ↓ |
| 스크롤백 클리어(CSI 3J) | 기본 | 기본 | **삼킴**(param==3만) ↓ |

### gjc 선택색 (`gjcSelectionBg`, `:306`)
gjc 는 xterm 로컬 선택을 쓰므로 `selectionBackground` 만 테마별로 덮음(`selectionForeground` 는 안 건드림 — 색기반 볼드 보존):
- soft(`#f2ede6`) → `#C2D8B0`
- minimal(`#f8fafc`) → `#C5D8F8`
- dark(그 외) → `#264F78`

### gjc Ctrl+C grace (`:420`)
gjc 는 생성 중 고빈도 풀 재페인트(`\x1b[2J`)가 xterm 선택을 지운다 → 드래그 직후 Ctrl+C 가 선택을 못 봐 SIGINT 로 빠져 gjc 중단됨. **최근 선택(800ms grace)** 이 있으면 그걸 복사하고 SIGINT 억제(`onSelectionChange` 로 `lastSelText`/`lastSelAt` 기록, `:751`). 한 번 더/grace 밖이면 정상 인터럽트.

### gjc 스크롤백 클리어 삼킴 (`:712`)
gjc(비멀티플렉서)는 풀 재페인트 때 `\x1b[3J` 로 스크롤백을 비운다 → 첫 휠 시 뷰포트가 맨 위로 튐. `param==3` 만 삼키고 ED 0/1/2(화면 지움)는 통과 → 과거 대화 스크롤 보존.

## 5. IME (한글 조합) — 아키텍처 전체

> 모든 로직은 `setupImeCaretFix()` (terminal.html, grep: `function setupImeCaretFix`) 안에 방(세션)별 클로저로 산다.
> 라인 번호는 변동되므로 **grep 앵커**로 찾을 것.

### 5-0. 문제 모델 (왜 전부 이 모양인가)

- IME 조합 문자열은 **확정 전까지 PTY 로 안 간다** → TUI 는 조합 존재 자체를 모름 → xterm 이 DOM 오버레이 `.composition-view` 로 미리보기를 그리고, 위치를 **논리(하드웨어) 커서**에 붙인다.
- xterm 내부 `updateCompositionElements` 는 커서가 viewport 밖이면 좌표 갱신을 **스킵** → CSS 초기값 `(0,0)` 잔류 = **좌상단 유령 조합**.
- 확정 글자의 **PTY echo 는 왕복 지연**(codex 수십 ms, opencode 는 렌더 배칭으로 수백 ms 가능)이 있다. 한글은 음절마다 `compositionend`→`compositionstart` 가 **같은 keydown 안에서** 연달아 발생 → 새 조합 시작 시점의 커서는 항상 "직전 글자 echo 도착 전" 좌표다.

**에이전트 2부류** — 신규 에이전트 추가 시 첫 판정:

| 부류 | 에이전트 | 특성 |
|---|---|---|
| **A. 자체커서형** | claude, gajae(gjc), grok | DECTCEM 으로 hw 커서 숨기고 자기 캐럿을 셀로 그림. 논리 커서는 아무데나 파킹 → 조합 중 커서 깜빡임 없음(자연스러움) |
| **B. hw커서형** | codex, opencode | hw 커서를 입력 캐럿에 둠. 유휴 시 xterm 기본 동기화로도 위치 정확. 단 ①응답 리페인트 중 커서가 출력/statusLine 왕복 ②echo 레이스 ③조합 중에도 블록커서가 계속 깜빡임 |

### 5-1. 증상 ↔ 원인 매트릭스

| 증상 | 원인 | 처방 |
|---|---|---|
| 조합 글자가 좌상단(0,0)에 뜸 | 커서 viewport 밖 → xterm 좌표 갱신 스킵 | pin |
| 조합이 여기저기 튐(응답 중 입력) | 리페인트마다 조합뷰가 논리 커서 추종 | pin(동결) |
| 직전 확정 글자를 조합이 덮음(연타) | 새 조합이 echo 미도착 좌표에 동결 | chain |
| 확정 자리가 빈칸으로 깜빡(연타) | chain 이 조합을 예측 위치로 옮긴 뒤 echo 지연 창 | ghost |
| 조합 중 블록커서 깜빡깜빡 | B형은 hw 커서 상시 표시 — 조합뷰/고스트(투명 배경) 밑에서 blink | hw 커서 숨김 |
| 타이핑 중 스크롤 밀리면 입력란+바로 윗줄 두 줄로 보임 | pin/ghost 는 viewport 상대 행 동결 — 스크롤로 입력란이 행 이동해도 옛 행에 잔류 | 스크롤 재고정 |
| 입력한 텍스트가 좌우로 이중으로 겹쳐 보임(가끔) | 일반 키(영문/스페이스) 직후 echo 지연 창에 조합 시작 → 앵커가 몇 칸 왼쪽 → chain 이 오차를 음절마다 전파 + ghost 가 틀린 자리에 그림 | 행 고정 추종 + 쓰레기 고스트 즉사 |
| 입력 글자가 하단 statusLine 우측 끝에 표시(codex/opencode) | statusLine 재묘화 후 커서가 그 끝(rows-1)에 파킹된 순간 조합 시작 → 그 좌표가 앵커로 동결 + chain 전파 | lastrow 가드(rows-1 앵커 금지, `anchor=lastrow-fallback`) — 폴백 좌표도 `row < rows-1` 검증, 폴백 없으면 no-pin 자가치유, chain 클램프 상한 rows-2 |

### 5-2. 처방 5종 (전부 `setupImeCaretFix` 내부, B형은 `pinsLogicalCaret` 게이트)

**① pin — 조합 중 위치 동결 + 행 고정 추종** (`.ime-fixed` + `--ime-left/top` CSS 변수)
- `compositionstart` 에 앵커 좌표 1회 스냅샷 → `frozenImeCaret` 으로 조합 내내 동결. xterm 이 0ms 루프로 인라인 left/top 을 되돌리므로 `!important` CSS 변수로 무력화(css grep: `.term-container.ime-fixed`).
- 앵커 소스가 부류별로 다름: **B형 = 논리 커서**(`buf.cursorY/X` 직독, grep: `rememberLogicalCaret`), **claude = 블록커서 스캔**(반전 빈 셀을 viewport 아래→위, 마지막 줄(상태바) 제외, 80ms 스로틀, 실패 시 `lastClaudeCaret` 캐시 폴백 `cached:true` — 60ms 재시도가 교정. 탭 show 직후 `_prepareImeCaret` 가 선스캔).
- **statusLine(rows-1) 앵커 금지**(B형, grep: `lastrow-fallback`): codex/opencode 는 statusLine 재묘화 후 커서를 그 끝에 파킹한다. 그 순간 조합이 시작되면 앵커가 statusLine 우측 끝에 동결 + chain 전파 → "입력 글자가 statusLine 끝에 표시". 커서가 rows-1 이면 마지막 유효 입력란 좌표로 폴백하되, 폴백도 `row < rows-1` 검증(리사이즈 stale 방지), 없으면 **no-pin**(null) — frozen 이 비므로 compositionupdate 재적용이 커서 복귀 즉시 자가 치유. chain 소비 클램프 상한도 rows-2. 앵커 판정은 `imeDiag` 로 `C:\devezLog\diag.log` 에 남는다(`anchor=live/chain/oob/lastrow-fallback`).
- **행 고정 추종**(B형, grep: `행 고정 추종`): 완전 동결이 아니라 **같은 행 안의 커서 이동은 앵커 교정으로 수용**한다. 직전 키(영문/스페이스/음절)의 echo 가 늦게 도착하면 조합 시작 앵커가 몇 칸 왼쪽으로 틀리는데, echo 도착 시 커서가 입력란 행에서 우측 이동 → 따라가면 자가 교정. 행이 다른 이동(출력영역/statusLine 왕복 = 원래 '커서 튐' 원인)만 무시. **이거 없으면 chain 이 앵커 오차를 음절마다 전파해 확정 텍스트 좌우 이중상**(실제 겪음).
- **스크롤 재고정**(B형, grep: `스크롤 재고정`): pin/ghost 좌표는 viewport 상대 행이라, 타이핑 중 출력이 스크롤을 밀면 옛 행에 잔류 → "입력란 + 바로 윗줄 두 줄" 유령. `term.onScroll` 에서 고스트 즉시 제거 + 조합 중이면 스크롤 진정 후 80ms 디바운스로 동결 해제·재고정(리페인트 종료 후 커서 = 새 입력란 캐럿. 즉시 재고정하면 바운스 좌표를 잡으므로 디바운스 필수).
- **`apply()` 는 반드시 `isImeComposing` 일 때만 동작**: `compositionstart+60ms` / `compositionupdate+0ms` 지연 타이머가 조합 종료 후 발화하면 `.ime-fixed` 재부착 + chain 오소모(실제 겪은 회귀).

**② chain — 확정 폭 전진 예약** (grep: `chainCaret`)

### 5-4. 시행착오 기록 (재시도 금지)

- **오프스크린(-9999px) 폴백**: "좌표 못 찾으면 화면 밖으로" — 지연 apply(조합 종료 후 발화)와 결합해 `.ime-fixed`+오프스크린이 잔류 → **조합이 통째로 안 보이는 회귀**. 폐기. 좌표 없으면 그냥 xterm 기본(잠깐 어긋남)이 낫다.
- **"응답 중 커서 전체 숨김"**: 폐기됨(이전 세션). 커서 숨김은 반드시 조합/고스트 창으로 한정.
- **pin 제거(d89754f)**: "논리 커서를 따라가게" — 응답 리페인트 중 조합뷰가 입력란↔statusLine 왕복. 원상복구됨. pin 은 필수.
- **chain 무효화에 keydown 만 사용**: 스페이스 확정을 못 잡음(keydown 은 `isComposing=true`) → 다음 조합이 1칸 왼쪽에 붙음. keyup 병행 필수.
- 지연 apply 타이머(60ms/0ms)는 조합 종료 후에도 발화한다 — `apply()` 안의 `isImeComposing` 가드 제거 금지.
- **조합 중 완전 동결(모든 커서 이동 무시)**: 직전 키 echo 지연으로 앵커가 틀린 채 시작하면 교정 기회가 없어 chain 이 오차를 전파 → 확정 텍스트 좌우 이중상. "같은 행 이동만 수용" 하는 행 고정 추종으로 대체됨 — 완전 동결로 되돌리지 말 것.
- **고스트 통짜 텍스트 렌더**: DOM 폰트 전진폭 ≠ xterm 셀 경계 → 여러 글자에서 드리프트 누적. 글자별 셀 고정 span 필수.

## 7. 스크롤 / 렌더링 커스터마이즈 (참고)

- **near-bottom sticky follow**(`writeOut`): 일반 터미널은 쓰기 직전 바닥 2줄 이내면 쓴 뒤 맨 아래로 붙임. 인라인 TUI인 codex/gjc는 고빈도 재페인트가 첫 위쪽 휠 반영 전에 바닥 스냅을 예약하지 않도록 `entry.follow`를 사용한다. 위쪽 휠/키 입력에서 즉시 `false`, 다시 논리적 바닥에 닿으면 `true`로 복원한다.
- **휠 다운 nudge 는 반드시 논리 줄 간격(`baseY - viewportY`)으로 판정** (커밋 160c93b): DOM 뷰포트 `scrollTop`(rest)은 codex 의 잦은 재페인트로 논리 ydisp 와 **크게 어긋난다**(위로 200줄 올려도 DOM 은 물리 바닥 `rest==0`. 실측 vpY=460/baseY=672/rest=0). 그래서 rest 로 판정하면 바닥에서 한참 위인데도 발동해 `scrollToBottom` 으로 바닥까지 끌려간다(="아래로는 휠 한 번에 바닥" 회귀. 위로 스크롤은 `deltaY<0` 이라 무영향 → 비대칭 증상). `gap = baseY - viewportY` 가 **1~3줄 이내**(입력창 잘림 보정 구간)일 때만 스냅, `gap<=0`(이미 논리 바닥)이면 skip. gjc 도 동일 경로. (구: `rest>=0 && rest<=cell*6` — 폐기)
- **탭 show 시 뷰포트 scrollTop 재동기**(`resyncViewportScroll`): 숨김(display:none) 중 출력이 쌓이면 DOM scrollTop 이 낡은 값으로 남아, 복귀 후 첫 휠에서 과거로 크게 점프. show 직후(더블 rAF + 220ms) 버퍼 위치(viewportY)에 맞춰 재동기.
- **`_scrollSuppress`**(`suppressScroll`, `:922`): 슬래시 명령 자동주입(/model·/effort) 후 N회 출력 동안 스크롤 위치 유지. 사용자가 휠 굴리면 즉시 해제(`:571`). 1.5s 후 강제 0.
- **`_pinBottomUntil`**(`pinBottom`, `:929`): 인라인 TUI(gjc) resume 재페인트 스크롤 튐 방지 — 지정 시각까지 쓰기 후 항상 맨 아래.
- **동기화 업데이트(?2026) 배칭**(`feedSync`, `:215`): gjc 멀티플렉서 repaint 를 open~close 한 번의 write 로 모아 입력창 튐 제거. 마커가 chunk 경계에서 잘리면 `syncCarry` 로 보류.
- **WebGL 렌더러**(`:638`): GPU 렌더. 소수 배율(125/150%)에선 커서 렌더 버그 → DOM 렌더러로 폴백(`disposeWebglIfFractional`, `:867`). GPU 컨텍스트 로스 시 자동 폴백. 원격/소프트웨어 렌더링에선 비활성.
- **전환 커튼(`xferCover`/`xferReveal`/`fadeNow`/`returnResync`)**: 분할·패널 토글 리플로우 깜빡임을 웹 레이어 단색/이미지 커버로 감춤. `_fitSuppressed` 로 중간 폭 fit 억제 → 최종 폭에서 한 번만 fit. (airspace 관련 상세는 커밋 히스토리·`airspace 깜빡임` 문서 참조)

## 8. 주의사항 (수정 시)

1. **`handleKey` 반환값 규약 절대 혼동 금지**: `false`=차단, `true`=통과. 새 단축키 추가 시 IME/AltGr 가드(`:405`) **뒤**에 두되, Ctrl+Enter 특례는 그 **앞**에 유지.
2. **마우스 모드 통과 정책**: claude 등의 DECSET 을 함부로 삼키지 말 것(휠/클릭 전달 깨짐). gjc 만 예외.
3. **클립보드는 반드시 STA + Win32 경로**: WPF `Clipboard.*` 직접 호출 금지(후킹 앱 데드락).
4. **오버레이·포커스는 웹 레이어 안에서만**: WebView2 airspace 때문에 WPF 오버레이로 터미널 못 덮음.
5. **조합뷰 `display:none` 금지**, 포커스 리포팅 억제 유지 — 안 그러면 한글 입력 깨짐.
6. **`Resources/Terminal/web/terminal.html` 이 원본**. `bin/` 은 빌드 복사본이니 편집 금지.
