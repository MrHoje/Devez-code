# 계정 관리 구현·검증 기록

검증일: 2026-09-10

## 사용 흐름

- 설정의 에이전트 바로 아래에 계정 메뉴를 추가했다. Claude와 Codex를 각각 관리한다.
- 계정 추가는 별칭 입력 없이 비공개 로그인 창에서 진행한다. 성공하면 이메일로 표시하며, 기존 CLI 인증은 변경하지 않는다. 기존에 저장한 별칭도 목록·콤보박스·알림에 표시하지 않는다.
- 계정 화면을 열면 Claude·Codex의 현재 CLI 계정을 처음부터 자동으로 가져온다. 기존 계정이면 ID를 유지하고 인증·이메일을 갱신한다. 현재 CLI 계정 가져오기 버튼으로도 다시 확인할 수 있다.
- 중복 판정은 이름·이메일이 아닌 공급자와 계정 식별자를 사용한다. Claude UUID는 대소문자를 구분하지 않고, Codex는 사용자와 워크스페이스를 함께 구분한다. 같은 이메일의 서로 다른 워크스페이스는 별도 항목이다.
- 한 공급자의 인증을 읽지 못해도 다른 공급자와 기존 등록 목록은 표시하며 오류를 안내한다. 변경 없는 재조회는 보관 파일을 다시 쓰지 않는다.
- 콤보박스에서 계정을 선택하면 변경한 공급자의 실행 중인 세션만 종료하고, 공통 설정·스킬·대화 기록 경로를 유지한 채 같은 방을 재개한다. Claude 변경은 Claude CLI·GUI와 Devez Vibe의 활성 Claude 공급자 세션, Codex 변경은 Codex CLI와 Devez Vibe의 활성 Codex 공급자 세션이 대상이다.
- Devez Vibe는 표시 ID 접두사 대신 `session-routes.json`의 `active`와 백엔드 ID 역조회로 공급자를 확인한다. 추적 ID의 라우트가 없으면 저장된 재개 ID로도 확인한다.
- 아직 첫 메시지를 보내지 않아 추적·저장 ID가 모두 없는 새 내부 세션은 계정 변경 뒤 다시 연다. 작업 중이거나 마지막 프롬프트가 남아 있으면 빈 세션으로 취급하지 않는다. 기존 대화가 있는 실행 중 세션의 공급자를 확인할 수 없으면 인증·세션을 변경하기 전에 전환을 중단한다.
- 휴면 세션은 강제로 시작하지 않는다. 이후 열 때 공통 인증 파일과 기존 재개 경로를 사용한다.
- 실행 중인 응답과 작성 중인 입력은 재시작 과정에서 중단될 수 있음을 화면에 표시한다.
- 계정 변경 중에는 안내 카드 아래의 진행 문구 왼쪽에 공용 회전 스피너를 표시하고 계정 조작을 잠근다. 진행 문구가 보이도록 스크롤하며, 종료 시 스피너를 숨기고 조작을 다시 허용한다.
- 변경할 공급자의 외부 터미널 세션이 있으면 먼저 닫도록 안내하고 전환을 막는다. 다른 공급자의 외부 세션은 영향을 받지 않는다. 앱이 추적하지 않는 해당 공급자의 독립 CLI도 사용자가 먼저 닫아야 한다.
- 사용 중인 계정의 삭제는 막고 이유를 툴팁으로 안내한다. 다른 계정으로 전환한 뒤 비활성 계정을 삭제할 수 있다. 삭제 확인은 공통 ConfirmDialog를 사용한다.

## 저장·실행 경계

- 등록 계정의 인증은 `%AppData%\DevezCode\accounts.dat`에 현재 Windows 사용자의 DPAPI로 암호화한다.
- CLI가 실제로 사용하는 인증 파일은 해당 CLI의 기존 형식으로 저장한다. 비활성 계정의 보관 파일을 평문으로 따로 만들지 않는다.
- Claude는 인증 파일과 전역 설정의 `oauthAccount`만 전환한다. 나머지 전역 설정과 프로젝트 신뢰 정보는 유지한다.
- Codex는 `auth.json`을 전환하고 인증 저장 방식을 `file`로 지정한다. 프로필의 인증 저장 옵션도 맞추며 모델·MCP·다중 행 지침은 유지한다.
- `CLAUDE_CONFIG_DIR`이 지정된 경우 `.claude.json`은 해당 디렉터리 내부를 사용한다. 설치된 Claude CLI를 임시 디렉터리에서 실행해 이 경로를 확인했다.
- 전환 전에 종료와 대화 기록 저장을 기다린다. 시작 중인 Claude GUI도 기다려 종료 대상에 포함하고, 전환 도중의 새 프로세스 생성과 중복 전환을 막는다.
- 저장 실패 시 변경한 인증·계정 정보를 복원한다. 복원이 불완전하면 자동 재실행을 멈추고 오류를 표시한다.
- 이전 계정의 사용량 응답과 훅 값이 다시 표시되지 않도록 요청 직렬화, 수집 시각 확인, 캐시 초기화를 적용한다. 관리 계정 선택 후에는 다른 계정의 사용량 인증으로 자동 폴백하지 않는다.
- 앱 자체의 종료·재시작이나 공개 배포는 수행하지 않았다. 기존 설치본은 계속 실행 중이며 새 코드는 `bin/DevezCode.exe`에 빌드했다.

## 확인하지 않은 범위

- 실계정의 브라우저 로그인, MFA, 서버 토큰 갱신과 한도 소진 후 두 계정 사이의 실제 모델 요청은 수행하지 않았다. 로컬 인증 형식 검사를 서버 인증 성공으로 취급하지 않는다.
- 실행 중인 사용자 세션을 직접 전환하지 않았다. 전체 앱의 실제 ConPTY·SDK 프로세스와 공급자 서버까지 연결한 전환은 사용자 계정으로 후속 확인이 필요하다.
- 물리 키보드 입력은 자동화하지 않았다. WPF 선택 패턴과 탭 탐색·포커스 스타일을 검사했다.

## 재현 명령

```powershell
dotnet build DevezCode.csproj -c Release --nologo -v quiet
dotnet run --project Tests/DevezCode.Accounts.Tests/DevezCode.Accounts.Tests.csproj -c Release -- --cli
dotnet run --project Tests/DevezCode.Tracking.Tests/DevezCode.Tracking.Tests.csproj -c Release
dotnet run --project Tests/DevezCode.Persistence.Tests/DevezCode.Persistence.Tests.csproj -c Release
& ./Tests/PersistenceSave.Tests.ps1
& ./Tests/TerminalSessionSwitchRender.Tests.ps1
& ./Tests/ThemeColors.Tests.ps1
```

계정 검사에는 설치된 Python을 사용해 현재 전환 메서드와 테마 팔레트를 추출한다. `--cli`를 생략하면 실제 CLI 실행 없이 독립 검사를 수행한다. 테스트의 프로세스·화면 대체 객체는 테스트 프로젝트 안에만 있다.
