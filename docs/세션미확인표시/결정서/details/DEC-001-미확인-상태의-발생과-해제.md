# DEC-001 미확인 상태의 발생과 해제

## 목적과 성공 기준

세션이 응답을 끝내거나 입력 대기에 들어간 순간을 사용자가 실제로 봤는지에 따라 "미확인" 여부를 정한다.
사용자가 자리를 비운 사이 끝난 세션, 분할 화면의 반대쪽 패널에서 끝난 세션, 설정 화면에 가려진 동안 끝난 세션을 놓치지 않는 것이 성공 기준이다.
미확인 상태는 사이드바·탭 표시(DEC-002)와 오른쪽 "세션 완료 기록" 패널의 카드 확인 상태가 **하나의 상태**로 함께 움직인다.

## 제약과 기존 결정

- 완료와 입력 대기는 앱이 이미 "확정"하는 지점이 있다(서브에이전트가 잠깐 쉬는 가짜 완료는 걸러진 지점). 미확인 상태도 이 확정 지점에서만 켠다. 확정 전의 순간적인 상태 변화에는 반응하지 않는다.
- 완료 확정은 응답이 멈춘 뒤 약 1.2초의 정착 시간을 거친 다음에 이뤄진다.
- 세션 완료 기록 패널(상단바 시계 아이콘, F3)은 이미 카드마다 확인 상태를 갖고 있고, 이 상태는 저장되어 재시작 후에도 남는다.
- 토스트 알림과 작업표시줄 깜빡임은 이 결정의 범위가 아니며 기존 동작을 유지한다.

## 영향을 받는 구성요소

- 세션 완료·입력 대기 확정 지점
- 사용자가 세션을 불러오는 동작(탭·행 클릭, 탭 재클릭, 프로젝트 카드 클릭, 알림·완료기록 카드 클릭, 빠른 열기, 단축키 이동)
- 앱이 세션을 띄우거나 다시 연결하는 동작(시작 시 복원, 분할 열기·닫기·복원, 탭을 닫은 뒤 옆 탭 표시, 옆 패널 프로젝트 동기화, 테마·세션 재시작, 외부 터미널 복귀, 숨김 종료 후 재연결)
- 터미널 화면·Claude GUI 화면의 사용자 조작
- 창 안 오버레이(설정·MCP 화면, 좁은 화면의 오른쪽 서랍)
- 세션 숨기기
- 세션 완료 기록 패널(카드 확인 상태, '모두 확인', 앱 시작 시 복원)

## 선택한 방향과 판단 근거

### 미확인이 켜지는 시점

완료 또는 입력 대기가 확정될 때, 사용자가 그 세션을 **보고 있었는지**를 판정한다.

"보고 있음"은 아래 조건을 **모두** 만족하는 상태다.

1. 앱 창이 앞에 있다(활성 창이고 최소화되지 않았다).
2. 설정·MCP 화면이나 오른쪽 서랍 같은 창 안 오버레이가 터미널을 가리고 있지 않다.
3. 그 세션이 **포커스된 패널**의 현재 화면이다(파일·브라우저 탭을 보고 있으면 세션을 보는 것이 아니다).

판정은 **응답이 멈춘 순간과 확정 순간 두 번** 한다. 둘 중 한 번이라도 보고 있었으면 본 것이다.

- 본 것이면: 표시하지 않는다. 그 세션에 이전부터 남아 있던 미확인 표시와 완료기록 카드의 미확인도 함께 해제한다.
- 보지 않았으면: 미확인으로 표시한다.
- 숨긴 세션은 본 것으로 친다(표시하지 않고 카드도 확인 상태로 쌓는다).

근거: 사용자가 선택한 기준은 "실제로 보고 있을 때만 확인으로 친다"이다. 확정이 1.2초 늦게 오므로, 멈추는 것을 보고 곧바로 다른 세션으로 옮긴 경우를 못 본 것으로 치지 않으려고 멈춘 순간도 함께 본다. 창 안 오버레이는 창이 활성이어도 터미널을 가리므로 보지 않은 것으로 친다.

### 미확인이 꺼지는 시점

다음은 **사용자가 그 세션을 확인한 것**으로 치고 해제한다. 해제는 사용자의 행동이 들어온 지점에서만 일어난다.

- 사용자가 그 세션을 불러온다: 탭·사이드바 행 클릭, 이미 떠 있는 탭 다시 클릭, 프로젝트 카드 클릭으로 그 프로젝트의 메인(왼쪽) 세션이 뜸, 알림·완료기록 카드 클릭, 빠른 열기, '분할 보기'로 옮긴 세션이 반대 패널에 열림, 단축키 이동(여러 칸을 한 번에 옮기면 도착한 세션만, 창을 실제로 앞으로 가져온 경우만).
- 그 세션이 떠 있는 패널의 터미널·Claude GUI 화면을 **직접 클릭하거나 키를 입력**한다.
- 그 세션을 숨긴다.
- 그 세션이 다시 끝나는 것을 보고 있었다(위 판정).
- 세션 완료 기록 패널에서 '모두 확인'을 누른다(모든 세션 해제).

다음은 확인으로 치지 **않는다**.

- 창이 다시 앞으로 오는 것만으로는 해제하지 않는다.
- Claude GUI 입력창에 포커스가 가는 것만으로는 해제하지 않는다(앱이 창 복귀·설정 닫기 때 자동으로 포커스를 돌려주기 때문).
- 앱이 스스로 세션을 띄우거나 다시 연결하는 경우는 사용자가 본 것이 아니므로 해제하지 않는다: 앱 시작 시 마지막 세션 복원, 분할 열기·닫기·복원, 탭을 닫은 뒤 옆 탭이 자동으로 뜸, 옆 패널의 프로젝트 동기화, 테마·세션 재시작, 외부 터미널 복귀, 숨김 종료 후 재연결.
근거: 사용자가 고른 선택지 설명대로, 탭을 열어 둔 채 다른 창에 다녀온 경우는 미확인으로 남고 돌아와서 그 패널을 조작해야 꺼진다. 해제를 "앱이 화면에 띄우는 모든 경우"에 걸고 예외를 빼는 방식은 새 경로가 생길 때마다 빠뜨리므로, 사용자 행동이 들어오는 지점에만 건다.

### 완료기록 카드와 하나의 상태로 묶는다

사이드바·탭의 미확인 표시는 따로 저장하지 않고 **"그 세션에 확인 안 된 완료기록 카드가 있다" 또는 "입력 대기 진입을 못 봤다"** 에서 계산한다. 응답 완료의 미확인은 곧 확인 안 된 카드다.

- 세션이 확인되면 그 세션의 완료기록 카드도 모두 확인 상태가 된다.
- 완료기록에서 '모두 확인'을 누르면 사이드바·탭 미확인 표시도 모두 꺼진다.
- 보고 있는 동안 끝난 응답은 완료기록 카드도 처음부터 확인 상태로 쌓인다.
- 카드를 지우면(개별 삭제, '모든 기록 지우기', 200장 한도에 밀려남) 그 카드로 생긴 사이드바 미확인도 함께 사라진다.
- 알림 없이 쌓이는 카드(가재코드 목표 완료 백필, Devez Vibe 압축 종료)는 응답 완료 확정이 아니므로 사이드바 미확인을 만들지 않는다. 카드 자체는 기존처럼 미확인으로 쌓이고(보고 있었거나 숨긴 세션이면 확인 상태로), 세션을 확인하면 함께 확인된다.
- 입력 대기 진입은 카드가 생기지 않으므로 세션에 따로 미확인을 표시한다. 세션 확인이나 '모두 확인'으로 함께 풀린다.
- 앱을 다시 켜면, 확인되지 않은 완료기록 카드가 남아 있는 세션을 미확인으로 되살린다. 숨긴 세션의 카드는 확인 상태로 정리한다.
- 이 기능이 들어가기 전부터 남아 있던 미확인 카드도 따로 정리하지 않고 같은 규칙으로 되살린다. 그동안 카드는 사이드바에서 세션을 열 때만 확인 상태가 됐으므로, 업데이트 후 첫 실행 때 이미 본 세션도 미확인으로 뜰 수 있다. 사용자가 세션을 열거나 '모두 확인'으로 정리한다.

근거: 2026-10-02 사용자 선택("하나로 묶기"). 두 표시를 따로 저장하고 손으로 맞추면 카드 삭제·한도 초과·재시작처럼 맞추는 곳을 빠뜨린 경로에서 어긋난다. 카드를 원천으로 삼아 사이드바를 계산하면 어떤 경로로 카드가 바뀌어도 두 곳이 같다. 알림 없는 카드는 턴 도중(압축 종료)이나 지난 시점(백필)에 생기므로, 사이드바 미확인의 "확정된 완료" 원칙에 맞지 않아 원천에서 뺀다.

## 적용 범위와 제외 범위

- 적용: 모든 에이전트 세션(터미널 세션, Claude GUI 세션, 외부 터미널로 넘긴 세션 포함).
- 제외: 파일 탭, 브라우저 탭.

## AI가 둔 가정

- **앱이 스스로 띄운 세션은 화면에 떠 있어도 확인으로 치지 않는다.** 탭을 닫아 옆 탭이 자동으로 뜨거나 앱 시작 시 마지막 세션이 복원되는 경우, 그 세션은 사용자가 터미널을 클릭하거나 키를 입력해야 해제된다. 앱 시작 시 되살린 미확인 표시가 사용자가 보기도 전에 지워지지 않게 하기 위해서다.
- **숨긴 세션의 완료·입력 대기는 본 것으로 친다.** 숨기기를 확인으로 치는 규칙과 맞춰, 숨긴 세션의 카드가 확인할 방법 없이 미확인으로 남지 않게 했다.
- **알림 없는 카드는 사이드바 미확인을 만들지 않는다.** 압축 종료는 턴 도중에 생기고 목표 완료 백필은 지난 시점의 기록이라, 응답이 확정된 순간에만 미확인을 켠다는 원칙과 맞지 않는다고 판단했다. 이 카드들만은 패널에서 미확인으로 보여도 사이드바에는 나타나지 않고, 그 세션을 열거나 화면을 조작하면 함께 확인된다.
- **이 기능 전에 저장된 알림 없는 카드는 압축 종료 카드만 알아본다.** 예전 카드에는 "알림 없는 카드" 표시가 없어서, 문구가 고정된 압축 종료 카드("Context compacted")만 구별할 수 있다. 예전 가재코드 목표 완료 백필 카드는 일반 완료 카드처럼 사이드바 미확인으로 되살아난다.
- **입력 대기 진입으로 생긴 미확인은 재시작 후 되살아나지 않는다.** 완료기록 카드는 응답 완료에만 생기기 때문이다. 재시작하면 세션이 다시 시작되어 입력 대기도 다시 판정된다.

## 결정의 검증 조건

- 창을 앞에 두고 포커스된 패널에서 보던 세션이 끝나면 표시가 생기지 않고, 완료기록 카드도 확인 상태로 쌓인다.
- 다른 창으로 전환한 뒤 그 세션이 끝나면, 돌아왔을 때 표시가 남아 있다. 터미널을 클릭하거나 키를 누르거나 그 탭을 다시 누르면 사라진다.
- Claude GUI 세션도 창으로 돌아오기만 해서는 표시가 사라지지 않고, 채팅 화면을 클릭하면 사라진다.
- 분할 화면에서 포커스되지 않은 쪽 세션이 끝나면 표시가 생긴다. 테마를 바꿔 세션이 재시작돼도 표시가 남는다.
- 설정 화면을 열어 둔 동안 끝난 세션은 설정을 닫은 뒤에도 표시가 남는다.
- 세션 응답이 멈추는 것을 보고 1초 안에 다른 세션으로 옮겨도, 앞 세션에 표시가 생기지 않는다.
- 사이드바에서 세션을 열면 사이드바 표시와 그 세션의 완료기록 카드 미확인이 함께 사라진다.
- 완료기록 '모두 확인'을 누르면 사이드바·탭 표시와 접힌 카드 숫자가 모두 사라진다.
- 미확인 세션의 카드를 지우면 사이드바 표시도 사라지고, 앱을 다시 켜도 되살아나지 않는다.
- Devez Vibe가 턴 도중 압축을 마쳐도 작업 중인 세션에 미확인 표시가 생기지 않는다.
- 미확인 카드가 남은 채로 앱을 다시 켜면, 그 세션이 사이드바에서 미확인으로 보인다. 시작 시 그 세션이 화면에 복원돼도 터미널을 조작하기 전까지는 표시가 남는다.
- 분할을 닫거나, 탭을 닫아 옆 탭이 떠도 그 세션의 표시는 남는다.
